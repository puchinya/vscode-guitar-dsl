# GuitarDSL 言語構文仕様書 (GuitarDSL Syntax Specification)

- Status: Current
- Owning Issue: [Issue #118](https://github.com/puchinya/vscode-guitar-dsl/issues/118)
- Related design: [Design index](../design/README.md), [Language and score processing](../design/language-and-score-processing.md), [Preview, rendering, and export](../design/preview-rendering-and-export.md), [Score editing](../design/score-editing.md), [Audio transcription](../design/audio-transcription.md)

本書は、ギター弾き語りおよびアコースティックギターストローク譜向けドメイン特化言語 **GuitarDSL** の言語構文、字句規則、およびレンダリング仕様を定義する規範的仕様書（Normative Public Contract）である。

---

## 1. 概要 (Overview)

GuitarDSL は、五線譜・リズムスラッシュ・ピッキング記号（ダウン／アップ）・コードネーム・コードダイアグラム・歌詞から構成されるポピュラー音楽向けリズム譜を、テキストベースで平易に記述するためのDSLである。

- **ファイル拡張子**: `.guitardsl`, `.gdsl`
- **文字エンコーディング**: UTF-8
- **言語種別**: 行指向の宣言的テキストフォーマット

### Purpose

本書は、GuitarDSL 文書の字句、構造、構文要素、意味、および描画に関する公開言語契約を定義する。

### Scope

対象は UTF-8 の `.guitardsl` / `.gdsl` 文書と §2–§18 に記載する解析および描画規則である。VS Code 固有のコマンドや UI 動作は[拡張機能仕様](extension.md)が所有する。

### Normative requirements

§2–§18 の構文規則、意味、制約、例、およびレンダリング要件を規範要件とする。本 Schema 2 化では既存の言語ルールや番号付きトップレベル節を変更しない。

### Observable behavior

適合する実装は本書の構文を読み取り、規定された診断・スコア表現・描画結果を生成する。構文要素ごとの入出力と表示規則は各節で定義する。

### Error and boundary behavior

不正、未対応、または境界外の入力の扱いは、各構文節と例に記載された規則に従う。拡張機能 UI や外部サービスの失敗境界は本書の対象外であり、拡張機能仕様が所有する。

### Security and privacy

この文書が定義するのはテキスト言語の構文と意味であり、ネットワークアクセスや資格情報の取り扱いは定義しない。拡張機能による外部サービスとの連携は[拡張機能仕様](extension.md)の対象である。

### Verification strategy

構文例と完全なサンプルをパーサー・診断・描画の適合確認に用いる。内部の解析・スコア処理経路は[言語とスコア処理設計](../design/language-and-score-processing.md)、表示経路は[プレビュー・描画設計](../design/preview-rendering-and-export.md)を参照する。

## 2. 字句構造 (Lexical Structure)

### 2.1 行指向性
GuitarDSL は行単位で解析される。1行は原則として以下のいずれかの要素を表す。
1. 空行
2. コメント行
3. メタデータヘッダー行
4. セクション見出し行
5. 小節行
6. 改ページ行 (Page Break)
7. メロディ行 (`mel:`、§12)
8. 音節歌詞行 (`lyr:`、§13)
9. コード定義行 (`chord`、§7.4)
10. スコアイベント行（`@key:` 等の途中変更・注記、§16）
11. フラグメント定義行（`let`、§17）

### 2.2 空行および空白文字
- 空行（改行のみ、または空白文字のみの行）は無視される。
- トークンを区切る連続した半角空白およびタブ文字は、単一の区切り文字として扱われる。

### 2.3 コメント
- `#` コメントは、コメント開始位置から行末まで構文解析時に無視される。コメント開始位置は構文ごとの規則に従う（メタデータヘッダーは §4.1、コード定義は §7.4.1）。
- 行頭からのコメントおよび行末コメントの双方が有効である。

```guitardsl
# これは行全体のコメントです
key: C # 行末コメント
```

## 3. ドキュメント構成 (Document Structure)

GuitarDSL ドキュメントは通常、以下の順序で構成される。

1. **ヘッダー部**: 楽曲のタイトル、アーティスト、キー、テンポ、カポ位置などのメタデータ
2. **編曲部（任意）**: ヘッダー部の後、スコア部の前に置く1つの `arrangement { ... }` ブロック
3. **スコア部**: セクション見出しおよび小節行からなる楽譜本体

編曲部は既存セクションの演奏順を指定する参照リストであり、小節の記述場所や書面の順序を変えない。編曲部を省略した文書は従来どおり演奏順を解決する。

## 4. メタデータヘッダー (Metadata Headers)

メタデータヘッダーは、楽曲全体の属性を定義する。

### 4.1 構文
```text
<key>: <value>
```
- キー名は大文字・小文字を区別しない（Case-insensitive）。
- コロン `:` の前後の空白はトリムされる。
- 値の先頭にある `#`、または値中で直前が半角スペースかタブである最初の `#` から行末まではコメントとして無視される。その `#` の直前にある区切り空白も値に含まれない。直前に空白やタブがない `#` は値の一部として残る。

```guitardsl
key: F# # 調のコメント（値は `F#`）
title: Song#1       # 値は `Song#1`
title: Song #1      # 値は `Song`
title: # コメントのみ（空の値）
```

- `tuning:` は曲頭のメタデータヘッダーに 1 回だけ書ける。省略時は Standard tuning を使う。本文開始後や `@tuning:` による調弦変更は定義しない。

### 4.2 サポートされるヘッダーキー一覧

| キー名 | 別名 | 説明 | デフォルト値 | 描画位置・役割 |
|---|---|---|---|---|
| `title` | - | 楽曲タイトル | `Guitar Rhythm Score` | ヘッダー最上部に大見出しで表示 |
| `artist` | - | アーティスト名／作詞・作曲者 | (空) | タイトル直下に `Words & Music: <artist>` として表示 |
| `capo` | - | カポタストの位置（フレット数） | `0` | 右上部に `Capo: <capo>` バッジとして表示 |
| `key` | `original_key` | 楽曲のキー（調） | `C` | 右上部に `Key: <key>` として表示 |
| `bpm` | `tempo` | テンポ（拍/分） | `90` | 右上部に `BPM: <bpm>` として表示 |
| `memo` | - | 演奏上の注意・メモ | (空) | ドキュメント内のメタ情報（将来拡張用） |
| `style_chord_size` | `chord_size` | コードネームの文字サイズ | `15px` | コードネームのフォントサイズ |
| `style_lyric_size` | `lyric_size` | 歌詞テキストの文字サイズ | `10px` | 五線下の歌詞フォントサイズ |
| `style_title_size` | `title_size` | タイトルの文字サイズ | `20pt` | 楽曲タイトルのフォントサイズ |
| `style_section_size` | `section_size` | セクションラベルの文字サイズ | `9.5px` | [Intro] 等の枠内フォントサイズ |
| `style_font_size` | `font_size`, `text_size` | 全体の基準フォントサイズ | `10pt` | 全体の基本フォントサイズ |
| `show_rhythm` | `rhythm` | リズム譜表の表示（`true` / `false`、`on` / `off`） | `true` | `false` でリードシートモード（§14.2） |
| `measures_per_row` | `bars_per_row` | 1段あたりの小節数（1〜8の整数） | `4` | 段の折り返し（§11）。範囲外・不正値は警告しデフォルト |
| `time` | `time_signature`, `meter` | 冒頭の拍子（§16.2） | `4/4` | 第1段の拍子記号・小節の長さの検証 |
| `feel` | - | 冒頭のフィール（`straight` / `swing` / `shuffle`、§16.6） | `straight` | 記譜上の注記のみ（音価の計算は変えない） |
| `pickup` | - | 弱起（アウフタクト）の長さ（音価、§16.3） | なし | 最初の小節の長さ |
| `tuning` | - | 6 弦ギターの調弦（§4.2「調弦値」） | `Standard` | コードフォームの実音・コード検出・弾きやすさに使う。`key` とメロディの実音は変えない |

- `key` / `bpm` / `time` / `feel` / `pickup` は**楽曲冒頭の値**を表す。曲の途中での変更はヘッダーではなくスコアイベント（`@key:` 等、§16）で書く。

#### 調弦値

`tuning:` の値には次の 5 つのプリセット、または 6 弦から 1 弦の順に並べた 6 個の科学的音高を指定する。

| プリセット | 第6弦から第1弦 | 半音番号（C4 = 60） |
|---|---|---|
| `Standard` | `E2 A2 D3 G3 B3 E4` | `40, 45, 50, 55, 59, 64` |
| `Drop D` | `D2 A2 D3 G3 B3 E4` | `38, 45, 50, 55, 59, 64` |
| `DADGAD` | `D2 A2 D3 G3 A3 D4` | `38, 45, 50, 55, 57, 62` |
| `Open G` | `D2 G2 D3 G3 B3 D4` | `38, 43, 50, 55, 59, 62` |
| `Open D` | `D2 A2 D3 F#3 A3 D4` | `38, 45, 50, 54, 57, 62` |

- プリセット名は大文字・小文字を区別せず、連続する空白を 1 つに正規化して照合する。
- 明示する各音高は `[A-Ga-g][#b]?[0-9]` に一致し、オクターブを必ず含める。音高は C4 = 60 の半音番号に変換し、異名同音は同じ半音として扱う。音高トークンは空白で区切る。カンマ区切り、7 弦以上の指定はできない。
- 既知のプリセット名以外で数字を含む値は明示調弦として解析する。不正な音高トークンがあれば弦数の判定より先にその音高エラーを報告し、全トークンが有効で 6 個以外なら弦数エラーを報告する。数字を含まない未知の値は未知プリセットエラーとする。
- 値の末尾の `#` コメントは既存ヘッダーと同じ規則で扱う（§2.3）。`C#4` の `#` は音高トークンの一部。
- 最初の `tuning:` ヘッダーだけを採用する。不正な値は Standard に回復し、後続の `tuning:` は重複として無視する。最初の `tuning:` が本文にある場合はヘッダー外エラーとして Standard を維持する。`@tuning:` は不正なスコアイベントとして扱う（拡張機能 §5A）。

### 4.3 記述例
```guitardsl
title: 風のコンパス - Wind Compass
artist: GuitarDSL Original
tuning: DADGAD
capo: 0
key: C
bpm: 104
memo: 軽快な8ビートストローク。
```

### 4.4 カポとコード名の意味論
- `capo` は物理的なカポタストの位置（フレット数）を表す。ヘッダーを省略した場合はカポ 0 とみなす。カポ変更・推論（拡張機能 §4B / §4.4）が扱う値は 0〜12 の整数に限る。それ以外の値（`capo: x`、`capo: 13` など）は表示上そのまま扱われるが、カポ変更の対象外となる。
- `tuning` は開放弦の音高を第6弦から第1弦の順に定める。ヘッダーを省略した場合は Standard を使う。
- 小節に書かれたコード名は、調弦とカポを基準に**押さえるフォーム（シェイプ）**を表す。各弦の実音は、その調弦の開放弦音高に物理的なカポ位置とフォーム上の相対フレットを加えて決まる。相対フレット 0 はカポ位置で押さえない弦を表す。Standard では従来どおり、`capo: 2` の `A` は B の響きになる。
- `key` / `original_key` は**実際に鳴る調**を表す。カポや調弦の位置によって変わらない。
- メロディ（`mel:` 行・小節内の音符）は実音で記譜する。カポや調弦によって変わらない。
- 鳴る響きを保ったままカポを `sourceCapo` から `targetCapo` に変える場合、書かれたコード名のルートとスラッシュのベース音を `targetCapo - sourceCapo` 半音だけ下げて書き直す。音名の綴りは `C, C#, D, Eb, E, F, F#, G, Ab, A, Bb, B` を使う。コードの種類（`m7` などのサフィックス）、長さの指定（`:2`、`/4.`）、`key`、メロディ、リズム、歌詞、BPM、セクション、繰り返し、コメント、改ページ、スタイルは変えない。
  - 例: `capo: 0` の `B` → `capo: 2` の `A`、`F#m` → `Em`、`E/G#` → `D/F#`。`capo: 3` の `C` → `capo: 5` の `Bb`。
- 弾きやすさ（難易度）は DSL に保存しない。`difficulty:` のようなヘッダーは定義しない。
- 曲の途中の転調 `@key:`（§16.4）も実際に鳴る調を表し、書かれたコード名・メロディを自動で書き換えない。カポはスコア全体で1つであり、途中でのカポ変更（`@capo`）は定義しない。

### 4.5 実音移調 (Sounding Transposition)
曲全体を `n` 半音（`-11`〜`+11`）移調する変換を以下のように定める。カポ変更（§4.4）とは別の操作であり、鳴る音そのものが変わる。

- 変わるもの: 冒頭の `key:` / `original_key:`、すべての `@key:`、小節に書かれたコード名のルートとスラッシュのベース音、`mel:` の音符、小節内の音高付き音符、`let` 定義に書かれた音符（使われていない定義も含む、定義の位置で1回だけ書き換える。§17）、同時複数音の各構成音（§18、常にオクターブ付きで書き直す）。
- 変わらないもの: カポ、BPM・テンポ記号、拍子、フィール、歌詞、音価、セクション、繰り返し・演奏順序記号、強弱・リハーサルマーク・テキスト、スタイル、コメント、空白、改行コード、`chord` 定義（押さえ方は移調しない）。
- 音名の綴りは `C, C#, D, Eb, E, F, F#, G, Ab, A, Bb, B` とする（元の異名同音の綴りは保持しない）。キーはルートを移調し、マイナーの `m` はそのまま残す。
- メロディ・音高付き音符はオクターブを含む半音数で移調し、上の綴りで書き直す（`b4` を +1 すると `c5`）。結果のオクターブが 0〜9 に収まらない場合、移調は失敗する。
- `0` 半音はカポ変更を伴わない限り何も変えない。
- `key:` / `original_key:` ヘッダーがない場合（鳴る調は既定の C）、移調後のキーを `key:` 行として追加する（最初の `bpm` / `tempo` / `time` / `feel` / `pickup` 行の前、なければ本文の最初の行の前）。
- 値の後の行末コメント（`key: A # メモ`）は保持し、値の部分だけを書き換える。
- 変換は書き換える値の部分だけを置き換え、それ以外のバイトを保持する。変換後の DSL に新しい構文エラーが出る場合、移調は失敗する。
- 移調できない場合（ドキュメントは変更しない）:
  - 移調量が 0 でなく、ラベル付きコード（`C@label`）を使っている。
  - 移調後のコード名が、別のコードを表すラベルなし `chord` 定義と同じ名前になる。
  - コード名を移調できない、または音高が範囲外になる。
- 使われなくなる `chord` 定義は削除せず、警告のみとする。
- 移調のあとにカポを変える場合（拡張機能 §4B.5）は、移調後の DSL に §4.4 の響きを保つカポ変更を行う。

## 5. セクション見出し (Section Headers)

楽曲の構造（Intro、Aメロ、サビなど）を示す見出しラベルを定義する。

### 5.1 構文
```text
[<セクション名>]
```
- 行頭が `[` で始まり、行末が `]` で終わる行がセクション見出しとして認識される。
- セクション名には英数字、記号、日本語（ひらがな・カタカナ・漢字等）を含む任意の文字列が使用可能。

### 5.2 振る舞い
- セクション見出しが定義されると、その直後に出現する**先頭の小節の上部**に、四角い枠線で囲まれたセクションボックスとして描画される。
- 1つのセクション指定は1回のみ消費され、後続の小節には引き継がれない。
- 編曲部がある文書では、セクション名は見出しの括弧内を大文字小文字・空白も含めて厳密に照合する。同名の見出し定義は曖昧になるためエラーとする。編曲部がない文書では、同名見出しを含め既存の振る舞いを保つ。

### 5.3 記述例
```guitardsl
[Intro]
| C | 4.d 4.d 4.d 4.d |

[サビ]
| F | 8.d 8.u 4.d 8.d 8.u 4.d |
```

## 6. 小節行と小節線 (Measures and Barlines)

楽譜の小節および小節線（小節区切り）を定義する。行内にパイプ記号 `|` が含まれる場合、小節行として解析される。

### 6.1 小節線記号 (Barlines)

| 記号 | 名称 | 説明・描画 |
|---|---|---|
| `\|` | 通常小節線 | 1本の細い縦線で小節を区切る。 |
| `\|:` | リピート開始線 | 左側に太線、右側に細線、および2つのリピートドットを描画。 |
| `:\|` | リピート終了線 | 左側に2つのリピートドット、細線、右側に太線を描画。 |

### 6.2 小節の記述形式

小節は以下のいずれかの形式で記述できる。

#### 形式A: 1小節内にコードとリズムを併記
```guitardsl
| C 4.d 4.d 4.d 4.d | G 4.d 4.d 4.d 4.d |
```

#### 形式B: コードセルとリズムセルを分割（推奨可読形式）
```guitardsl
| C  | 4.d 4.d 4.d 4.d |
| G  | 4.d 4.d 4.d 4.d |
```
- パーサーは、「コードのみを含むセル」の直後に「リズムのみを含むセル」が存在する場合、それらを単一の小節データとして自動結合（マージ）する。

### 6.3 小節内のトークンと行の継続
- 小節のセルに書けるのは、コード（§7）、リズムトークン（§8）、インラインの音符・同時複数音（§12, §18）、`$name`（§17）、`%`（§8.7）、1番・2番カッコ、演奏順序記号（§8.8）、`l:"..."`（§9）だけである。これ以外のトークン（例: 小節行に書いた歌詞のかな、`N.C.`）は **エラー**（`unknownMeasureToken`）とし、そのトークンを無視する（描画は継続）。
- 行の継続（折り返し）の構文はない。`mel:` 行・`lyr:` 行の直後（空行を挟まない）に、行頭が空白で始まる `|` の行を書いた場合（その行の直後の同様の行も含む）は **エラー**（`unsupportedContinuationLine`）とし、その行は小節として読まない。複数小節のメロディ・歌詞は 1 行に書くか、行ごとに `mel:` / `lyr:` を付ける（§12.3, §13.1）。

#### 形式C: リピート記号を含む小節
```guitardsl
|: C | 4.d 4.d 4.d 4.d |
|  F | 4.d 4.d 4.d 4.d :|
```

## 7. コード表記 (Chords)

各小節で演奏するギターの和音（コードネーム）を指定する。

### 7.1 構文規則
コードトークンは以下の正規表現パターンに合致する文字列である。

```regex
^[A-G][b#]?(maj|m|min|aug|dim|sus[24]|add9|[0-9]+)*(\/[A-G][b#]?)?$
```

- **ルート音**: `A` 〜 `G`（必要に応じて半音下げ `b` または半音上げ `#`）
- **コードクオリティ / テンション**:
  - メジャー / マイナー: `m`, `min`, `maj`
  - サスペンデッド: `sus2`, `sus4`
  - オーグメント / ディミニッシュ: `aug`, `dim`
  - セブンス / ナインス / テンション: `7`, `maj7`, `m7`, `add9` 等
- **オンコード（分数コード）**: スラッシュ記号 `/` に続けてベース音を指定（例: `G/B`, `D/F#`）
- **ダイアグラムの指定（任意）**: コード名の直後に `@<ラベル>` を付けると、§7.4 で定義したその押さえ方のダイアグラムを使う（例: `C@barre`）。ラベルは英数字と `_`（`[A-Za-z0-9_]+`）。長さを付けるときはラベルの後に書く（`C@barre:2`、`G/B@alt/2`）。五線譜上では、コード名の右上にラベルを小さい灰色の上付き文字で添える（リズム段・メロディ段とも。同じコード名の押さえ方が1種類しかなくても表示する）。

### 7.2 1小節内の複数コードチェンジ (Multiple Chords per Measure)
1小節内で2回以上のコードチェンジを行う場合、以下の記法をサポートする。

#### 1. 形式B（セル分割形式・均等配分）
コードセルに複数のコードを半角空白区切りで並べる。
```guitardsl
| C G | 8.d 8.u 4.d 8.d 8.u 4.d |
```
- 目印（拍指定）のない場合、小節の拍数に応じて均等に配分される（4/4拍子で2コードの場合、0拍目から2拍分が `C`、2拍目から2拍分が `G` となる）。

#### 2. 形式B（セル分割形式・長さ指定）
不均等なコードチェンジ（例: 3拍＋1拍）や、シンコペーションによるコードチェンジ（例: 2拍目の裏でチェンジ）を行う場合、コードの直後に長さを付与する。長さは次の2通りで書ける（1小節内で混在してよい）。

| 区切り | 意味 | 例 |
|---|---|---|
| `:` | **拍数**（4分音符 = 1、小数可） | `C:2.5 G:1.5`、`C:3 G:1` |
| `/` | **音価**（§8.2.1 共通音価表記） | `C/2+8 G/4.`、`C/2. G/4` |

```guitardsl
| C:3 G:1       | 4.d 4.d 4.d 4.d |
| C/2+8 G/4.    | 4.d 8.d 8.u.a 8.u 8.d 8.d 8.u |
| G/B/2 D/F#/2  | 4.d 4.d 4.d 4.d |
```
- 分数コードのベース音指定（`/B`）と音価（`/2`）は、`/` の直後が英字（ベース音）か数字（音価）かで区別する。分数コードに長さを付ける場合はベース音の後に続ける（`G/B/2`、`G/B:2`）。
- 長さ指定のないコードは 2 拍として扱う。
- 長さとして不正な値はエラー診断となり、その小節のコードは均等配分で配置される。

#### 3. 形式A（インライン形式）
リズムトークンの間にコードを直接記述する。
```guitardsl
| C 4.d 4.d G 4.d 4.d |
| C 4.d 8.d G 8.u 4.d 8.d 8.u |
```
- リズムの累積拍位置に応じて、各コードが配置されたタイミングでコードチェンジが行われる。

### 7.3 コードダイアグラム (Chord Diagrams)
スコア内で一度でも使用されたコードは自動的に収集され、楽譜上部のダイアグラム領域にフレット指板図として一覧描画される（小節内に複数コードがある場合もすべて網羅される）。

- 収集の単位は「コード名 + ラベル」である。`C` と `C@barre` を両方使うと、ダイアグラムは2枚描かれる。並び順は最初に使われた順。
- 各ダイアグラムの押さえ方は、次の順に決まる。
  1. ファイル内にある、そのキー（`C@barre` なら `C@barre`）の `chord` 定義（§7.4）
  2. ラベル付きで該当する定義がない場合は、ラベルなしの定義（`C`）
  3. 組み込みのプリセットライブラリ（下記）にある、コード名全体（分数コードなら `G/B` のようにベース音を含む名前）の既定の押さえ方。Standard では従来の順序をそのまま使う。別の調弦では Standard のプリセット形を対象の調弦で鳴らし、コード名と一致する形だけを元の順序で残す。
  4. 分数コードでコード名全体の既定の押さえ方がない場合は、上部コード（`F/A` なら `F`）の既定の押さえ方。同じ調弦でコード名と一致する形だけを使う。
  5. どれにも当てはまらない場合は、既定のフォールバック形状（`xx0232`）
- 分数コード専用のプリセット（`G/B`, `D/F#`）がある場合は、上部コードの押さえ方より優先する。
- 手順 1〜4 で決まる押さえ方は、カポの弾きやすさ評価（`docs/specs/extension.md` §4B.3）と初心者モード（同 §4.5）の評価にも同じものを使う。フォールバック形状は表示のための仮の図であり、弾きやすさ評価では押さえ方不明のコードとして扱う。
- 別の調弦でプリセット形がコード名に一致しない場合、その形を意味上の解決結果として使わない。適合形がなければ意味上の押さえ方は未解決となる。明示的な `chord` 定義はプリセット照合で除外しない。フォーム名の検出ではカポを 0 として扱い、物理的な実音を計算するときだけスコアのカポを加える。
- 組み込みプリセットライブラリ:
  - 手書きの基本形（既定の押さえ方として優先する）: `C`, `G`, `D`, `A`, `E`, `F`, `Am`, `Em`, `Dm`, `B7`, `Dm7`, `Am7`, `Em7`, `G7`, `C7`, `A7`, `E7`, `Bm7`, `Fmaj7`, `Cmaj7`, `Cadd9`, `G/B`, `D/F#`
  - 12 のルート（`C C# D Eb E F F# G Ab A Bb B`）× 15 のタイプ（`maj m 7 maj7 m7 sus2 sus4 7sus4 6 m6 add9 9 m9 dim aug`）について、移動できる形（E 型・A 型・D 型・C 型・G 型）をルートに合わせて平行移動した押さえ方。15 フレットを超えるもの、押弦の幅が 5 フレットを超えるものは含めない。
  - 上記以外のコード名（ルートの異名同音 `D#` 等は同じピッチとして扱う。`min` は `m` と同じ）はライブラリで解決されない。分数コードでライブラリに直接あるのは手書きの基本形のものだけで、それ以外は上部コードの押さえ方を使う（上記の手順 4）。
- ダイアグラムの描画内容:
  - 6 本の弦と 5 フレット分の枠。ミュート弦の `×`、開放弦の `○`、押弦位置の黒丸。
  - 開始フレットが 1 のときは太いナットを描く。2 以上のときはナットを細線にして、枠の左に開始フレット番号を描く。
  - セーハ（`barre`）は、対象の弦の範囲をまたぐ角丸のバーで描く。
  - 指番号（`fingers`）があれば、枠の下に各弦の指番号を描く。
  - コード名の下に、ラベルを小さい灰色の文字で描く（ラベル付きのダイアグラムのみ）。五線譜上の上付きラベル（§7.1）と同じ文字列なので、どのダイアグラムを使うか対応が取れる。
  - プリセットライブラリの押さえ方には、押弦が 5 本以上あり開放弦を使わない場合、最低フレットにセーハを付ける。

### 7.4 コード定義 (Chord Definitions)
ダイアグラムの押さえ方をファイル内で定義する。同じコード名に `@ラベル` を付けて、押さえ方を何通りでも定義できる。

#### 7.4.1 構文
```text
chord <コード名>[@<ラベル>] = <フレット> [base:<n>] [fingers:<指番号>] [barre:<フレット>[:<弦>-<弦>]]...
```
- 行頭の `chord` の後に空白が続く行をコード定義行とする（大文字・小文字を区別しない）。ファイル内のどこに書いてもよいが、通常はヘッダー部に書く。
- `<コード名>` は §7.1 の構文に従う。`<ラベル>` は `[A-Za-z0-9_]+`。ラベルのない定義が、そのコード名の既定の押さえ方になる。
- `<フレット>` は 6 弦から 1 弦の順に 6 つ書く。
  - すべて 1 桁のときは続けて書ける（`x32010`）。2 桁のフレットがあるときはカンマで区切る（`x,x,10,9,8,8`）。
  - `x` はミュート、`0` または `o` はカポ位置の開放弦、数値はカポからの相対フレット（0〜24）。`capo: 0` では従来と同じ位置になる。物理フレットは `capo` と相対フレットの合計であり、24 を超えない。
- オプション（順不同。`barre` は複数書ける）:

| オプション | 値 | 意味 |
|---|---|---|
| `base:<n>` | 1〜24 | カポから数えた図の開始フレット。省略すると自動で決める（押弦の最高フレットが 5 以下なら 1、そうでなければ押弦の最低フレット） |
| `fingers:<6文字>` | `-`、`1`〜`4`、`T` | 6 弦から 1 弦の順の指番号。`-` は指番号なし、`T` は親指 |
| `barre:<f>` | 相対フレット | 相対フレット `<f>` のセーハ。範囲は、そのフレットを押さえている最低弦から最高弦まで |
| `barre:<f>:<a>-<b>` | 相対フレット、弦番号 1〜6 | 弦 `<a>` から `<b>` までのセーハ（例: `barre:3:5-1`） |

- 行末コメント（空白の後の `#` 以降）は無視する。`C#` のように音名に続く `#` はコメントではない。

#### 7.4.2 参照と解決
- 小節内のコードトークン `<コード名>@<ラベル>` で、その定義を参照する（§7.1）。
- ラベルのない `<コード名>` は、ラベルのない定義があればそれを、なければプリセットライブラリを使う（§7.3）。
- 定義の位置と参照の位置の前後関係は問わない。

#### 7.4.3 診断
| コード | 重大度 | 条件 | 振る舞い |
|---|---|---|---|
| `invalidChordDefinition` | エラー | 構文、コード名、ラベル、フレット、オプションの値が不正。または押弦位置（セーハを含む）が開始フレットから 5 フレットの範囲に収まらない、あるいは最終の調弦・カポで物理フレット 24 を超える | その行を無視する |
| `duplicateChordDefinition` | 警告 | 最終の調弦・カポで有効な同じ `コード名@ラベル`（ラベルなし同士を含む）の定義が 2 回以上ある | 最初の有効定義を使う。不正な行はキーを占有しない |
| `unknownChordVariant` | 警告 | 参照 `C@x` に対応する定義がない | ラベルのない `C` の解決結果で描く |

コード定義は全行を読み取った後、スコアの最終的な調弦・カポで妥当性を確認する。不正な定義は重複判定のキーを予約せず、ラベル参照も有効な定義だけを使って検証する。

#### 7.4.4 記述例
```guitardsl
title: Voicing Sample
chord C       = x32010
chord C@barre = x35553 fingers:-13331 barre:3
chord C@high  = x,x,10,9,8,8 fingers:--4312

[Intro]
| C | 4.d 4.d 4.d 4.d |
| C@barre:2 C@high:2 | 4.d 4.d 4.d 4.d |
```

## 8. リズム・ストローク記法 (Rhythm and Stroke Tokens)

各小節内のストロークパターン、ピッキング方向、アクセント、音価を定義する。

### 8.1 トークン書式
```text
<音価>[.<修飾子1>.<修飾子2>...]
```
ドット `.` で区切ることで、音価に対して複数の修飾子（ピッキング方向、表現など）を付与する。

### 8.2 音価 (Duration)

| 指定値 | 名称 | 楽譜上での意味・描画表現 |
|---|---|---|
| `1` または `w` | 全音符 (Whole note) | 4拍分の長さ。幅広の白抜きスラッシュヘッド（符幹なし）として小節中央に描画 |
| `2` または `h` | 2分音符 (Half note) | 2拍分の長さ。白抜きのスラッシュヘッド＋符幹として描画 |
| `4` または `q` | 4分音符 (Quarter note) | 1拍分の長さ。黒塗りのスラッシュヘッド＋符幹として描画 |
| `8` | 8分音符 (Eighth note) | 1/2拍分の長さ。黒塗りスラッシュヘッド＋符幹。同拍内の音符とは太い連桁（ビーム）で結線（孤立時は旗） |
| `16` | 16分音符 (Sixteenth note) | 1/4拍分の長さ。黒塗りスラッシュヘッド＋符幹。同拍内の音符とは二重連桁（ビーム）で結線（孤立時は二重旗） |
| `8t` `4t` `16t` | 3連符 | 基本音価の 2/3 の長さ。拍単位でグループ化し括弧＋「3」を描画 |
| `8{5:4}` 等 | 連符（一般） | 基本音価 × `normal / actual` の長さ（§8.2.1）。同じ比率の連続を1グループとし「actual」の数字を描画 |
| `4+8` 等 | 加算 | 各項の和の長さ。項ごとのスラッシュをタイで結んで描画 |

リズムトークンでは `.` が修飾子区切りであるため、付点は加算で表す（付点4分 = `4+8.d`）。

#### 8.2.1 共通音価表記 (Note Value Notation)
コードの長さ指定の `/` 形式（§7.2）、メロディ音符の `/` 形式（§12）で共通に用いる音価表記を以下に定める。リズムトークン（§8.2）も付点 `.` を除き同じ規則に従う。

```text
音価     := 項 ( "+" 項 )*
項       := 基本音価 ( "." | "t" | 連符比 )?
連符比   := "{" 実数 ":" 通常数 "}"        （実数・通常数は 2〜16 の整数で、互いに異なる）
基本音価 := "1" | "2" | "4" | "8" | "16"
```

| 表記 | 意味 | 拍数（4分音符 = 1） |
|---|---|---|
| `1` `2` `4` `8` `16` | 全・2分・4分・8分・16分音符 | 4, 2, 1, 1/2, 1/4 |
| `2.` `4.` `8.` | 付点（1.5 倍） | 3, 3/2, 3/4 |
| `4t` `8t` `16t` | 3連符（2/3 倍） | 2/3, 1/3, 1/6 |
| `2+8` | 加算 | 5/2 |
| `8{5:4}` `8{6:4}` `16{7:4}` | 連符（`actual:normal`、基本音価 × normal / actual） | 2/5, 1/3, 1/7 |

- 拍数の合計は有理数として厳密に扱う（`8t` ×3 = 1 拍、`8{5:4}` ×5 = 2 拍）。
- `t` は `{3:2}` と同じ意味である。
- 連符比の数が 2〜16 の整数でない、または `actual` と `normal` が等しい場合はエラー（`8{1:1}`、`8{0:4}`、`8{17:16}`）。
- 同じ比率の連符が連続する部分を1グループとし、小節線をまたいでグループを作らない。グループの合計が `normal` 個分の基本音価（例: `8{5:4}` なら 8分音符4個 = 2拍、`8t` なら 8分音符2個 = 1拍）ごとに1つの括弧・数字を描画する。比率の異なる音符・小節線までにグループが完結しない場合は警告。
- 小節の合計がその小節の拍子（§16.2）の長さと一致しない場合は警告診断となる（描画は継続）。

### 8.3 休符 (Rest)
- 音価の先頭に `r` を付与することで休符となる（例: `r1`, `rw`, `r2`, `rh`, `r4`, `rq`, `r8`, `r16`）。
- 楽譜上には音価別のベクター休符記号（全休符: 第4線吊り下げ、2分休符: 第3線上、4分休符、8分休符、16分休符）として描画され、スラッシュヘッドやピッキング記号は描画されない。

### 8.4 修飾子 (Modifiers)

| 修飾子 | 完全名 | 名称 | 描画・効果 |
|---|---|---|---|
| `d` | - | ダウンストローク | スラッシュ上部にダウンピッキング記号（`п`）を描画 |
| `u` | - | アップストローク | スラッシュ上部にアップピッキング記号（`∨`）を描画 |
| `g` | `ghost` | ゴーストノート | ブラッシング／ミュートストローク。透明度35%で薄く描画 |
| `a` | `accent` | アクセント | スラッシュ上部にアクセント記号（`>`）を描画 |
| `t` | `tie` | タイ | 音を伸ばすタイ属性（後続音との連結情報） |
| `arp` | `arpeggio` | アルペジアート | スラッシュ（音符）の左に波線（分散和音記号）を描画 |
| `pm` | - | パームミュート | 段の上の奏法欄に `P.M.` と破線を描画。連続する `pm` は1本の範囲にまとめる |
| `lr` | - | レットリング | 段の上の奏法欄に `let ring` と破線を描画。連続する `lr` は1本の範囲にまとめる |
| `stacc` | - | スタッカート | スラッシュの下に点を描画 |
| `ten` | - | テヌート | スラッシュの下に短い横線を描画 |
| `fermata` | - | フェルマータ | 段の上の奏法欄にフェルマータを描画（休符にも付けられる） |
| `vib` | - | ビブラート | 段の上の奏法欄に波線を描画 |
| `breath` | - | ブレス | スラッシュの右上にブレス記号を描画（休符にも付けられる） |

- 休符に付けられる修飾子は `fermata` と `breath` のみ（それ以外の奏法修飾子はエラー）。
- 音高を必要とする奏法（`hammer` `pull` `slide` `gliss` `bend` `grace` `slur-start` `slur-end`）は音高のないスラッシュには付けられない（エラー）。これらは小節内の音高付き音符または `mel:` の音符に §12.2 の奏法ブロックで書く。
- 範囲（`pm` / `lr`）が段をまたぐ場合は、段ごとに分けて描画する（次の段の頭から続きを描く）。

### 8.5 記述例
- `4.d`: 4分音符のダウンストローク
- `8.u`: 8分音符のアップストローク
- `16.d.a`: 16分音符のダウンストローク（アクセント付き）
- `8.d.g` または `8.d.ghost`: 8分音符のダウングーストノート（ブラッシング）
- `1.d`: 1小節伸ばす全音符ダウンストローク

### 8.6 リズム省略時のデフォルト補完
小節内にリズムトークンが1つも指定されていない場合、パーサーは自動的に以下のデフォルトリズム（4分音符4拍）を補完する。
- 1拍目: `4.d`（4分音符ダウンストローク）
- 2拍目: `4`（4分音符ストローク方向なし）
- 3拍目: `4.d`（4分音符ダウンストローク）
- 4拍目: `4`（4分音符ストローク方向なし）

4/4 以外の拍子（§16.2）では、拍子の単位音符（分母）を分子の数だけ並べ、各拍グループの先頭をダウンストローク（`.d`）とする（例: 3/4 は `4.d 4.d 4.d`、6/8 は `8.d 8 8 8.d 8 8`）。

### 8.7 小節の繰り返し記号 (Measure Repeat Sign / Simile Mark)
前小節のリズムパターンをそのまま繰り返すことを示す記号として、パーセント記号 `%` を使用できる。

- **記法**:
  - **形式B（セル分割形式）**:
    ```guitardsl
    | Am Em | % l:"あたらしいドアを ひらく" |
    ```
  - **形式A（インライン形式）**:
    ```guitardsl
    | Am Em % l:"あたらしいドアを ひらく" |
    ```
  - **コード省略**:
    ```guitardsl
    | % l:"歌詞テキスト" |
    | % |
    ```
    コードセルまたはコード指定を省略した場合は、直前小節のコード（単一または複数）がそのまま自動的に引き継がれる。
- **振る舞い・描画**:
  - 五線譜の中央（第3線を中心）に、太い斜線と上下2つのドットからなる標準的なメジャーリピート記号（`%`）が描画される。
  - 当該小節の通常のスラッシュ符頭、符幹、連桁、ピッキング記号、アクセントは非表示となる。
  - 小節に指定されたコードネーム（単一または複数）は上部に、歌詞テキストは下部に通常通り描画される。
- **拍子の境界**: 繰り返す元の小節と `%` の小節の拍子（§16.2）が異なる場合はエラーとし、元の小節を伸縮して複製しない（`mel:` の `%` セルも同じ）。

### 8.8 反復記号・小節線・演奏順序記号

#### 書かれた順序と演奏順序
- `|:`、`:|`、カッコ、ナビゲーション記号から、実際に演奏する小節の順序を決定する。各演奏回は小節の出現として扱い、書かれた小節の `measureIndex` を保つ。演奏回の番号は0から連続する。
- `ParsedScore.measures` と各ページの小節は常に書かれた順序のままとする。レンダリング順を演奏順に並べ替えない。
- 改ページは描画上の区切りであり、演奏順解決では参照しない。同じセクション内で連続する volta の所有関係は改ページだけでは切れない。
- `%` は通常の書かれた小節として演奏順に現れる。前小節の音楽的内容の展開は §8.7 の責務であり、演奏順 resolver は `%` の `measureIndex` を前小節に置き換えない。

#### 反復小節線 (Repeat Barlines) と実行
- `|:`: 反復開始線（左側に太線＋細線＋2つのドット）
- `:|`: 反復終了線（右側に2つのドット＋細線＋太線）
- `|::|`: 連続する反復線
- 明示的な `|:` と `:|` は対応付けて反復区間を作る。ネストした区間では、`:|` は最も内側の未終了区間を閉じる。反復は通常合計2回演奏する。
- 対応する明示的な `|:` がない `:|` には、パーサーは引き続き警告（`repeatEndWithoutStart`）を報告するが、描画と演奏順解決は続行する。演奏順では暗黙の反復区間として扱い、直前のセクション見出しから始める。該当する見出しがなければ楽譜の先頭から始める。
- volta のカッコは終了セグメントの最初の小節に記述する。後続のカッコのない小節も、終了小節の `:|` まで同じセグメントに含める。セグメント中のすべての小節にカッコを繰り返し書く必要はない。カッコに一致しない演奏回ではセグメント全体を飛ばすが、その終端の `:|` は次の演奏回や終了を決める制御として評価する。
- 1番・2番など連続する volta の終了セグメントは同じ反復区間を共有する。終了セグメントの `:|` はその区間の反復制御として評価し、新しい暗黙の反復区間を作らない。終端の `:|` がない最終セグメントは、次の volta、新しい反復開始、またはセクション境界まで続く。終了セグメント内のカッコのない小節は連続を切らないが、終了したセグメントと次の volta の間にあるカッコのない小節、新しい `|:`、またはセクション見出しは共有を切る。改ページだけでは演奏順上の連続は終わらない。
- パーサーの `repeatEndWithoutStart` 警告は、書かれた記法の検査であり、演奏順が無効であることを意味しない。警告を抑制する判定は演奏順の所有関係とは別で、現在のパーサー規則どおりページ境界も考慮する。
- 反復ブロック内の volta は最も内側のブロックが所有する。ブラケットに正の整数のリストまたは範囲（例: `[1,3-4.]`）を記述でき、ピリオドは番号の後または末尾に付けられる。`0` 以下、降順の範囲、空の要素、不正な書式、安全な整数でない値はエラーとする。
- ブロックの演奏回数は、2回と、所有する volta に書かれた最大の番号のうち大きい方とする。小節は現在の演奏回数がブラケットに含まれる場合だけ演奏する。小節が飛ばされても、その小節の `:|` などの反復制御は評価する。
- volta が飛ばされた位置の `:|` の後ろに、現在の演奏回数に一致する同じブロックの volta がある場合は、その終了小節へ進む。それ以外は `:|` の反復制御に従って次の演奏回へ戻るか、反復区間を抜ける。
- 外側の反復が次の回に戻るとき、内側の反復回数は1回目に戻す。

#### 1番・2番カッコ (Volta Brackets)
- `[1.]`, `[2.]`, `[1,2.]`, `[1-2.]`: 終了セグメントの最初の小節に記述する。カッコの範囲は複数小節でもよく、後続のカッコのない小節もセグメントの `:|` まで含む。
  - `:|` と併用された終了小節では右端の縦フックが閉じられる。
  - 例: `|: C G | [1.] Am Em :| [2.] F G ||`
- 反復区間に割り当てられない volta はエラーとする。書式が不正な volta もエラーとする。

#### 演奏順序記号 (Navigation / Jump Marks)
- `Fine`, `D.C.`, `D.S.`, `Coda`, `to Coda`, `Segno`: 小節内に記述することで、小節上部に演奏指示記号を描画する。
  - `Segno`: 𝄋
  - `Coda` / `to Coda`: 𝄌
  - `Fine`: *Fine*
  - `D.C.`: *D.C.*
  - `D.S.`: *D.S.*
- 楽譜全体の主ジャンプは `D.C.` または `D.S.` のどちらか1つまでとする。複数ある場合はエラーにし、いずれかを選んで演奏を続けない。
- `D.C.` は記号の小節を演奏した後に楽譜の先頭へ1回戻る。`D.S.` は唯一の `Segno` の小節へ1回戻る。`D.S.` に対応する `Segno` がない、または複数ある場合はエラーとする。`Segno` と `Coda` の位置は通常の演奏可能な小節である。
- ジャンプ前の `Fine` と `to Coda` は演奏制御として無視する。`D.C.` または `D.S.` の後は、最初に到達して演奏した `Fine` の小節を演奏して終了する。
- `D.C.` または `D.S.` の後、最初に到達して演奏した `to Coda` の小節を演奏した後、唯一の `Coda` へ1回ジャンプする。その後の `to Coda` は無視する。主ジャンプがあり、書かれた楽譜のどこかに `to Coda` がある場合、到達可能性によらず `Coda` がちょうど1つ必要である。ない場合または複数ある場合はエラーとする。主ジャンプのない楽譜にある `Fine` / `to Coda` / `Coda` は描画のみで、単独では演奏順エラーにしない。
- 主ジャンプ後は反復の後戻りを行わない。volta の選択では、各反復区間を最終演奏回にいるものとして扱う。飛ばされた小節の `Fine`、`to Coda`、`D.C.`、`D.S.` は演奏制御として無視し、その小節の反復制御だけを評価する。
- 同じ小節の制御順は、主ジャンプ後の `Fine` 終了、未使用の `to Coda`、未使用の `D.C.` / `D.S.`、反復終了、通常の次小節の順とする。1回の小節出現で2つの制御ジャンプは実行しない。

#### 演奏順エラーと上限
- 曖昧または不正な演奏順（複数の主ジャンプ、移動先の不足または重複、不正または所有先のない volta、終了しない明示反復など）はエラーとする。エラー時はパースと描画を続けるが、演奏順は無効とし、部分的な演奏小節列を返さない。
- 演奏小節出現の上限は100,000回とし、超過時は部分的な列を返さず `playOrderLimitExceeded` をエラーとして診断する。
- `playOrderMultipleNavigationJumps`、`playOrderMissingDestination`、`playOrderAmbiguousDestination`、`playOrderInvalidVolta`、`playOrderVoltaWithoutRepeat`、`playOrderUnclosedRepeat`、`playOrderLimitExceeded` はすべてエラーとして診断する。

#### セクション編曲 (`arrangement { ... }`)
- メタデータヘッダーの後、スコア部の前に、文書あたり1つの小文字固定 `arrangement {` ～ `}` ブロックを置ける。空行・コメント行・末尾の空白と `#` コメントは無視する。ブロック内には少なくとも1つの参照を書く。旧構文 `arrangement:` と `end_arrangement` は受理しない。
- 1行の参照は `<name>[(lyr=<N>)][ x<M>]`。通常名は Unicode の英字または `_` で始まり、Unicode の英数字・`_`・`-` が続く名前とする。空白やその他の記号を含む既存見出し名は、見出しと同じ括弧を含めて `[Verse A]` のように指定する。`lyr` と `x` は小文字でこの順に書く。`N` と `M` は1以上の10進 safe integer、`x<M>` の省略は1回を表す。参照は前方にも書ける。同じ参照を繰り返すこともできる。
- 参照先セクションは見出しの直後の小節から次の見出し直前までとする。`pagebreak` は範囲を分割しない。空セクション、編曲部があるのに最初の見出しより前にある小節はエラーとする。一意で未参照のセクションは有効。
- 編曲部がある文書では、明示反復 `|:` / `:|`、volta、Segno、Coda、`to Coda`、Fine、D.C.、D.S. は参照された範囲に限らずエラーとする。`%`、通常線・複縦線・終止線、改ページは使用できる。参照範囲を小節単位で連結し、同じ演奏順 resolver が1回だけ出現列を作る。書面の小節・ページ・全番歌詞は複製・並べ替えない。
- 各参照の `x<M>` は独立した出現に展開する。自動歌詞番号は同名セクションの出現ごとに独立して進み、各セクションで利用できる番数を巡回する。詳細は §13.2 を参照。展開前に各参照と合計の上限100,000件を検査し、エラー時は部分的な演奏順を返さない。
- 構文、重複ブロック、終端・配置、空ブロック、重複・空セクション、未割り当て小節、未知・曖昧な参照、編曲とナビゲーション記号の競合、利用できない歌詞番は位置付きエラーとする。演奏順上限超過も `playOrderLimitExceeded` として参照位置に診断する。

#### 複縦線・終止線 (Double and Final Barlines)
- `||`: 複縦線（セクションの区切り等。細線2本）
- `|]`: 終止線（楽曲の終了。細線＋太線）

## 9. 歌詞記法 (Lyrics)

小節内の該当位置に対応する歌詞テキストを指定する。

### 9.1 構文
```text
l:"<歌詞テキスト>"
```
または
```text
~"<歌詞テキスト>"
```
- ダブルクォート `"` で囲まれた文字列が歌詞として抽出される。
- 小節内の任意の位置（通常は小節末尾）に記述可能。

### 9.2 描画
- 当該小節の五線譜最下線の真下（中央揃え）に歌詞テキストとしてレンダリングされる。
- メロディ（§12）が割り当てられた小節では、音符単位の歌詞（§13）を用いる。同一小節に `l:"..."` とメロディが両方ある場合は警告診断となり、`l:"..."` は描画されない。メロディのない小節では従来通り `l:"..."` を用いる。

### 9.3 記述例
```guitardsl
| C | 8.d 16.d 16.u 8.d 8.u 4.d l:"あさのひかりを あびながら" |
```

## 10. 改ページ記法 (Page Breaks)

楽譜内の明示的なページ区切り（改ページ）を定義する。

### 10.1 構文
```text
---
```
または
```text
pagebreak
```
- 行頭から行末までが3文字以上のハイフン `---`（または `-` の連続）、あるいはキーワード `pagebreak`（大文字・小文字不問）のみで構成される行が改ページ行として認識される。
- 前後に任意の半角空白またはタブが含まれていてもよい。

### 10.2 振る舞い
- コンパイラは改ページ行を検出すると、後続の小節行やセクション見出しを新しいページ（`ScorePage`）としてグループ化する。
- 1ページ目にはフルヘッダー（曲名、アーティスト、キー、テンポ、カポ、コードダイアグラム）が描画される。
- 2ページ目以降の先頭には、曲名とページ番号（例: `風のコンパス - p. 2`）からなるランニングヘッダーがコンパクトに描画される。

## 11. レンダリング・レイアウト仕様 (Rendering and Layout Rules)

GuitarDSL コンパイラが生成する SVG / HTML 楽譜の表示規則は以下の通りである。

1. **システム（段）構成**:
   - 各ページ内の小節は**1段あたり `measures_per_row` 小節（デフォルト4）**で自動的に折り返される。改ページが行われると、次の小節は新しいページの第1段先頭に配置される。
   - 調の変更（`@key:`）と拍子の変更（`@time:`）は、その小節から新しい段を始める（すでに段頭の場合を除く）。これは改ページではなく、自動改ページにより次のページへ送られることはあっても、ページを強制しない。値が変わらない `@key:` / `@time:` は段を区切らない。それ以外のイベント（テンポ、フィール、強弱、テキスト等）は段を区切らない。`measures_per_row` はそれ以外の折り返しの上限として働く。
   - 各段の全幅は 780px、各小節は均等に割り振られる。
   - メロディのない小節では、小節内の各リズム符（スラッシュ・休符）は等間隔（Equal Spacing）で配置される。
   - メロディのある小節では、リズム符とメロディ音符の発音拍の和集合を列として等間隔に並べ、メロディ譜表とリズム譜表の同じ拍を縦に揃える。
   - 段の高さはメロディの有無・歌詞の番数・`show_rhythm` により段ごとに決まる。メロディのない段の高さは従来通り（段座標 140）。
2. **段頭の記号**:
   - すべての段の先頭に五線とト音記号（Treble Clef）が描画される。
   - メロディ譜表では、ト音記号の直後に調号（§14.1）が描画される。
   - 第1段と、拍子の変更（`@time:`）で始まる段にのみ、その拍子の拍子記号（分子・分母を縦に積んだ数字）を調号の直後に表示する。通常の折り返しでは繰り返さない。
   - 調の変更で始まる段では、メロディ譜表に前の調号の打ち消し（ナチュラル）が必要な場合はそれを描画してから新しい調号を描画する。メロディのない段（リズム譜表のみ）では調号の代わりに、その小節の上に `Key: D` のようなテキストを表示する。
   - 第1小節線の x 座標は全段で揃える（§14.1）。
3. **垂直レイアウト順（メロディのない段、上から下）**:
   1. セクション名（`[Intro]` 等の枠付きラベル: y=6〜22）
   2. コードネーム（太字テキスト: baseline y=32）
   3. アクセント記号（`>`: y=38〜44）
   4. ピッキング記号（`п`, `∨`: y=47〜52）
   5. 連桁・符幹（Beams / Stems: y=60〜79）
   6. 五線譜（Stave Lines: 5本線 y=70, 78, 86, 94, 102）およびリズムスラッシュヘッド（第3線 y=86 を中心に配置、全音符・2分音符は白抜き、4分音符以下は黒塗り）
   7. 歌詞テキスト（五線下部 y=120）

   メロディのある段（上から下）: セクション名 → コードネーム → メロディ譜表（加線・臨時記号を含む）→ 音符単位の歌詞（番数分）→ リズム譜表（上記 3〜7 と同じ構成）。`show_rhythm: false` の場合はリズム譜表を省略する（§14.2）。

   メロディのある段（リードシートを含む）では、セクション名・コードネーム（ラベルを含む）・繰り返しのカギ線・演奏指示記号（Fine 等）をまとめて五線側へ下げ、その分だけ段を低くする。下げる量は段ごとに決め、見出しの下端（コードネームの基準線 + 文字サイズの 1/4）とメロディ譜表の最も高いインク（符頭・臨時記号・符幹・連桁・連符番号・五線より上の弧・スタッカート・テヌート・フェルマータ・ビブラート・ベンド・装飾音）の間を 8 以上空ける。五線より上に何もない段では、コードネームの基準線から五線上端までが約 19 になる。高い音や記号で空きがない段は下げない（従来と同じ位置）。メロディのない段は上記 1〜7 の位置のまま変えない。

   スコアイベント（§16）と奏法の範囲記号は、段の上の注記欄と段の下の強弱欄に描画する。注記欄は上から リハーサルマーク → テンポ・フィール → テキスト（リズムのみの段の `Key:` 表示を含む）→ オッターヴァ → 奏法範囲（`P.M.`、`let ring`、リズム譜表のフェルマータ・ビブラート）の順で、段に必要な欄だけを確保する。欄はコード名の上の空き（セクション名・括弧・演奏順序記号・高い音がない段）に重ねて五線に近づけ、足りない分だけ段の高さを増やす（隣の段・ページ内の他の要素と重ならない）。強弱記号は段の最下部の強弱欄、つまり一番下の五線（その下の歌詞・低い音・記号を含む）のすぐ下に描画し、段の下の余白に収まらない分だけ段の高さを増やす。
4. **プレビュー表示モード (Preview Display Modes)**:
   - プレビュー画面上部に固定ツールバー（Toolbar）が提供され、以下の表示方法をいつでも切り替え可能:
     - **1ページ表示（デフォルト）**: Wordの印刷レイアウトやPDFリーダーのように、選択した用紙枠が縦に並び、自然に縦スクロールして閲覧できる表示。
     - **見開き表示**: 見開き2ページを左右横並びで表示し、縦スクロール可能。
     - **Web表示（シームレス）**: 用紙枠や改ページ余白、ページ番号等の用紙概念を排除し、全小節が下までシームレスに続く表示。改ページ記法 `---` の位置には控えめな細い点線（`Page Break`）を表示。
5. **用紙設定と見開きPDF保存**:
   - ツールバーにて用紙サイズ（A3 / A4 [標準] / A5 / B4 / B5 / Letter）および向き（縦向き / 横向き）を選択可能。
   - 横向き（Landscape）選択時は、1枚の横向き用紙に2ページ（見開き）を割り付けた見開きPDF（2-up Spread Print）として出力される。
6. **PDF保存機能**:
   - ツールバーの「PDF保存」ボタンから、指定した用紙サイズ・向きで高品質なベクトルPDFを直接生成・保存できる。
   - 印刷機能は非対応（PDF保存に一本化）。

## 12. メロディライン (Melody Line)

小節行とは別に、歌のメロディ（音高と音価）を記述する。

### 12.1 構文
```text
mel: | <音符> <音符> ... | <音符> ... |
```
- 行頭が `mel:` の行をメロディ行とする。`|` で区切られた各セルが1小節分のメロディである。
- セル `%` は直前の小節のメロディを複製する（歌詞は複製しない）。直前の小節にメロディがない場合はエラー。

### 12.2 音符トークン
```text
音符 := 音名 臨時記号? オクターブ? 長さ? "~"?
休符 := "r" 長さ?
長さ := "/" 音価 | ":" 拍数           （音価は §8.2.1、拍数は 4分音符 = 1 の数値）
音名 := "a" | "b" | "c" | "d" | "e" | "f" | "g"     （小文字のみ）
臨時記号 := "#" | "b"
オクターブ := 0〜9 の数字（科学的音高表記、c4 = 中央ハ）
```
- 例: `e4/8`（E4 の8分音符）、`f#4/4`、`bb3/2`（B♭3 の2分音符）、`a4/4.`（付点4分）、`b4/8t`（8分3連）、`c5/8{5:4}`（8分5連）、`g4/2~`（次の音符へタイ）、`r/8`（8分休符）。拍数でも書ける（`e4:0.5` = `e4/8`）。
- 長さは、コードと同じく `/` の音価（§8.2.1）または `:` の拍数で書く。メロディの `:` 拍数は 1/4 拍の倍数に限る（描画時に付点・タイで音符に分解する）。3連符は `/` の音価（`8t` 等）で書く。
- **継承**: オクターブと長さを省略すると、同じ `mel:` 行内の直前の音符の値を引き継ぐ。各 `mel:` 行の最初の音符ではオクターブと長さを省略できない（エラー）。休符はオクターブを持たない。
- 大文字の音名はエラー（コードネームとの区別のため）。
- 同時複数音 `[c4,e4,g4]/4`（§18）と `let` フラグメントの参照 `$name`（§17）も1つの音符トークンの位置に書ける。どちらも前後の音符のオクターブ・長さの継承に参加しない。
- 音高は実音（歌のピッチ）で記述し、ト音記号の譜表に描画する。調号があっても常に実際の音高を書く（D メジャーでも `f#4`）。

#### 12.2.1 奏法ブロック (Techniques)
音符（`mel:` の音符、および小節内の音高付き音符）には、長さの後・タイ `~` の前に奏法ブロックを1つ付けられる。

```text
音符     := 音名 臨時記号? オクターブ? 長さ? 奏法ブロック? "~"?
休符     := "r" 長さ? 奏法ブロック?
奏法ブロック := "{" 奏法 ( "," 奏法 )* "}"
奏法     := "hammer" | "pull" | "slide" | "gliss" | "vibrato" | "staccato" | "tenuto" | "fermata"
          | "breath" | "grace" | "slur-start" | "slur-end" | "pm" | "let-ring" | "bend:" 半音数
```

- 連符比 `{5:4}` は長さの一部であり、数字の対で始まる。奏法ブロックは名前で始まるため区別できる（`c5/8{5:4}{staccato}`）。
- `bend:` の半音数は 0.5 刻みの 0.5〜4.0。記譜上の表示のみで、音符の音高は変えない（表示は 1 = `½`、2 = `full`、3 = `1½`、4 = `2`）。
- 未知の奏法名、同じ奏法の重複、両立しない組み合わせ（`hammer` `pull` `slide` `gliss` のうち2つ以上、`slur-start` と `slur-end` の同時指定）はエラー。
- 休符に付けられるのは `fermata` と `breath` のみ（それ以外はエラー）。
- **接続**: `hammer`（`H`）・`pull`（`P`）・`slide`・`gliss` は、その音符から**次に鳴る装飾音でない音符**（休符・装飾音符は飛ばす）へ接続する。`hammer` と `pull` を音高の上下から推定し直すことはしない。接続先がない場合は警告。
  - `mel:` の音符は曲全体のメロディの並びで、小節内の音高付き音符は曲全体の小節内音符の並びで次の音符を探す（小節線をまたいでよい）。
- **スラー**: `slur-start` から次の `slur-end` までを1本のスラーとする（入れ子不可）。入れ子の `slur-start`、対応のない `slur-end`、閉じられていない `slur-start` は警告とし、描画は継続する。
- 段をまたぐ接続・スラーは、始点の段の終わりまでと、終点の段の頭からの2つに分けて描画する（ページをまたいで1本の線を描かない）。
- **装飾音符** (`grace`): 拍数 0 として扱い、小節の長さの検証・拍位置を進めない。長さは符頭・旗の形だけに使う。次の拍を持つ音符の左に小さく描画し、連続する装飾音符は記述順に並べる。歌詞の音節を取らない。装飾音符は直前の音符の長さを継承せず、後続の音符が継承する長さも変えない（長さを省略した装飾音符は8分音符の形で描く。オクターブは通常どおり継承・更新する）。同じ小節内で後に拍を持つ音符がない場合は警告。
- 描画: `hammer` / `pull` は弧＋`H` / `P`、`slide` は斜線、`gliss` は波線＋`gliss.`、`bend` は上向きの曲線矢印＋量、`vibrato` は短い波線、`staccato` は点、`tenuto` は短い横線、`fermata` は弧＋点、`breath` はコンマ状の記号、スラーは弧、`pm` は `P.M.`＋破線、`let-ring` は `let ring`＋破線。

### 12.3 小節への割り当て
- `mel:` 行の各セルは、**まだメロディが割り当てられていない最も前の小節**から順に割り当てられる。したがって、小節行1行ごとに `mel:` を書いても、複数小節の後にまとめて書いてもよい。
- セクション見出しおよび改ページを越えて割り当てることはない（それ以前の未割り当て小節はメロディなしとなる）。
- セル数が未割り当て小節数を超える場合、超過分はエラー。
- メロディが割り当てられない小節はメロディなしとして描画される。
- 小節内の合計が、その小節の拍子（§16.2）の長さと一致しない場合は警告（装飾音符は 0 拍、§12.2.1）。

### 12.4 描画
- 符頭（全・2分は白抜き、4分以下は黒塗り）、加線、付点、符幹（B4 より下は上向き、B4 以上は下向き）、拍単位の連桁、旗、休符、タイ（段をまたぐ場合は段末までの弧）、3連符の括弧と「3」を描画する。
- 臨時記号は調号（§14.1）と小節内の状態から必要な場合のみ描画する。小節内では持続し、小節線でリセットされる。調号や直前の臨時記号を打ち消す場合はナチュラルを描画する。タイで持ち越した音符には描画しない。

### 12.5 記述例
```guitardsl
| C  | 8.d 8.u 4.d 8.d 8.u 4.d |
| G  | % |
mel: | r/8 e4/8 e g a g e d | d4/8 d e d c/4 r/4 |
lyr: | あさの ひかりを      | あびなが ら         |
```

## 13. 音符単位の歌詞 (Syllable Lyrics)

### 13.1 構文
```text
lyr: <音節> <音節> ... [| ...]
```
- 行頭が `lyr:` の行を音節歌詞行とする。直前の `mel:` 行が割り当てた音符列に対応する。
- 1つの `mel:` 行の後に続く n 行目の `lyr:` 行が n 番の歌詞となる。
- `mel:` 行より前に現れた `lyr:` 行はエラー。
- `arrangement { ... }` の `Section(lyr=N)` は、その出現で選ぶ歌詞番を1-basedで指定する。省略時は同名セクションの演奏出現順に自動選択する。これは出現メタデータであり、書面にある `lyr:` 行や楽譜上の全番表示を変更しない。

### 13.2 音節の割り当て
- 休符とタイの継続側の音符を除いた音符に、先頭から順に1音節ずつ割り当てる。
- 日本語（かな・漢字等）は1文字を1音節とする。ただし小書き文字 `ゃゅょぁぃぅぇぉゎ`（カタカナも同様）は直前の文字と結合する。`っ` `ー` は独立した1音節とする。
- 英数字は空白で区切られた単位を1音節とする。音節末尾の `-` は同一単語の続きを示し（例: `sun- shine`）、音節間にハイフンを描画する。
- `(ひか)` のように括弧で囲んだ文字列は1音節として扱う。
- `_` は直前の音節の延長（メリスマ）で、その音符には延長線を描画する。
- `*` は歌詞なしで1音符を飛ばす。
- `|` は任意。記述した場合は小節の境界と照合し、ずれていれば警告。
- 音節が音符より多い・少ない場合は警告（不足した音符は歌詞なし）。
- 編曲参照に `lyr=N` を指定した場合、該当セクションの歌唱対象を持つ `mel:` グループすべてに N 番がなければエラーとする。自動選択の番数は、それらのグループの `verseCount` の最小値とする。歌詞のないグループは無歌詞のまま、固定インライン歌詞は切り替えない。利用できる番数が0なら自動選択メタデータを付けない。
- 出現ごとの選択値 `lyricVerse?` は演奏順 occurrence と Preview timeline に引き継ぐ。現行の楽譜 Preview / PDF の歌詞描画は書面どおりとし、再生画面に歌詞オーバーレイを追加しない。

### 13.3 描画
- 各音節は対応する符頭の x 座標に中央揃えで、メロディ譜表の下に描画する。複数番は上から 1番, 2番, … の順に行を重ねる。

## 14. 調号・表示設定 (Key Signature and Display Options)

### 14.1 調号
- `key:` ヘッダーの値から調号を決定する。書式は `<ルート>[b|#][m]`（例: `C`, `G`, `Bb`, `F#m`, `Am`）。メジャーは `C`〜`C#`、`Cb`、マイナーは対応する平行調（♯・♭ 最大7個）。
- 解析できない値の場合は調号なし（ヘッダーのテキスト表示のみ）。
- 調号はメロディ譜表の各段頭に、その段の最初の小節で有効な調（`@key:` による転調を含む、§16.4）の調号を描画する（リズム譜表には描画しない）。
- 小節の開始位置（第1小節線の x）は全段で共通とし、いずれかの段頭で必要になる最大の幅（ト音記号、打ち消しのナチュラルを含む調号、表示する拍子記号）を確保する。幅の小さい段頭は余白となる。

### 14.2 リードシートモード (`show_rhythm: false`)
- メロディのある段ではリズム譜表を描画せず、セクション名 → コードネーム → メロディ譜表 → 歌詞 の構成とする。
- 同じ段にメロディのない小節がある場合、その小節にはメロディ譜表上に拍ごとのスラッシュ（ピッキング記号なし）を描画する。
- 段全体にメロディがない場合は、通常のリズム譜表で描画する。

### 14.3 段あたり小節数 (`measures_per_row`)
- 1〜8 の整数で1段あたりの小節数を指定する。範囲外・不正値は警告診断とし、デフォルト 4 を用いる。

## 16. スコアイベントと途中変更 (Score Events)

曲の途中で調・テンポ・拍子・フィール・オッターヴァを変えたり、強弱・リハーサルマーク・テキストを付けたりするには、スコアイベント行を使う。

### 16.1 構文
```text
@<名前>: <値>
```
- 行頭（前の空白は可）が `@` で始まる行をスコアイベント行とする。名前は大文字・小文字を区別しない。値の前後の空白は除き、空白に続く `#` 以降はコメント（§2.3）とする。
- スコアイベントは**次の小節**の直前に適用される。1行に複数の小節を書いた場合、その途中にイベントを置くことはできない（変えたい小節を次の行に書き、その前にイベント行を置く）。
- 同じ小節の前に複数のイベントを書いてよい。記述順を保つ。
- 最後の小節より後のイベントは警告とし、描画しない。
- 不正なイベント（未知の名前、不正な値）はエラーとし、現在の状態を変えない（解析は継続する）。

| イベント | 別名 | 値 | 種類 |
|---|---|---|---|
| `@key:` | - | キー（`D`, `F#m`, `Bb` 等、§14.1 の書式で解析できること） | 持続（次の変更まで） |
| `@tempo:` | `@bpm:`（数値のみ） | 正の数値（BPM）、`rit.`、`accel.`、`a tempo`、`tempo primo` | 数値は持続、文字の記号はその小節の注記 |
| `@time:` | `@meter:` | 拍子（§16.2） | 持続 |
| `@feel:` | - | `straight` / `swing` / `shuffle` | 持続 |
| `@dynamic:` | - | `ppp` `pp` `p` `mp` `mf` `f` `ff` `fff` `sfz` `fp` | その小節の注記 |
| `@mark:` | - | リハーサルマーク（空でない文字列） | その小節の注記 |
| `@text:` | - | 演奏指示などのテキスト（空でない文字列） | その小節の注記 |
| `@ottava:` | - | `8va` / `8vb` / `off` | 持続 |

`@capo` は定義しない（カポはスコア全体で1つ、§4.4）。

```guitardsl
key: C
bpm: 120
| C | G |
@key: D
@tempo: 132
@dynamic: f
| D | A |
@time: 7/8(2+2+3)
@mark: B
| Em | 8.d 8.u 8.d 8.u 8.d 8.u 8.d |
```

### 16.2 拍子
```text
拍子 := 分子 "/" 分母 ( "(" グループ ( "+" グループ )* ")" )?
```
- 分子は 1〜32 の整数、分母は `1` `2` `4` `8` `16` のいずれか。
- 1小節の長さ（4分音符 = 1 拍）は `分子 × 4 / 分母`（例: 3/4 = 3 拍、6/8 = 3 拍、7/8 = 3.5 拍）。小節の長さの検証、コード・音符の横位置、連桁のまとまりは、その小節で有効な拍子を使う。
- グループ（拍のまとまり）を書く場合、各グループは分子より小さい正の整数で、合計が分子に等しいこと（不一致はエラー）。
- グループを省略した場合: 分母が 8 または 16 で分子が 3 より大きい 3 の倍数なら 3 ずつ（6/8 → 3+3、9/8 → 3+3+3）、そうでなく分子が 5 以上の奇数なら 2 ずつで最後を 3（5/8 → 2+3、7/8 → 2+2+3）、それ以外は 1 ずつ（4/4 → 1+1+1+1）。
- 連桁（8分・16分音符のまとまり）はグループ単位（グループ1つ = 分母の音符 × グループの数）で区切る。4/4 では従来どおり1拍ごと。
- 冒頭の拍子は `time:` ヘッダー（既定 4/4）、途中の変更は `@time:`。

### 16.3 弱起 (Pickup)
- `pickup:` ヘッダーは冒頭の値としてのみ有効で、音価（§8.2.1、例: `pickup: 4`、`pickup: 8+8+8`）で書く。0 より大きく、冒頭の拍子の1小節より短いこと（それ以外はエラー）。
- 弱起があると、最初の小節の長さは弱起の長さで検証する。
- 最後の小節は、弱起があり、その小節の拍子が冒頭の拍子と同じで、長さがちょうど `1小節 − 弱起` の場合に限り、長さの警告を出さない。それ以外は通常どおり検証する（最後の拍子が変わっている場合は補完しない）。
- 弱起は繰り返し・演奏順序記号の意味を変えない。

### 16.4 転調 (`@key:`)
- 次の小節から有効な実際に鳴る調を変える。メロディ譜表の調号、臨時記号の判定はその小節から新しい調で行う（前の小節の臨時記号は持ち越さない。タイで続く音符には臨時記号を重ねて描かない）。
- 書かれたコード名・メロディは自動で書き換えない。
- `key:` ヘッダーの値（冒頭の調、楽譜ヘッダーの `Key:` 表示）は変わらない。

### 16.5 テンポ (`@tempo:`)
- 数値はその小節以降のテンポ（BPM）を変える。段の上に `♩ = 132` の形で表示する。
- Preview 再生では数値テンポをその小節から適用する。
- `rit.` / `accel.` / `a tempo` は表示のみ（斜体）。再生テンポの補間や変更は行わない。
- `tempo primo` は `Tempo primo` と表示し、冒頭の `bpm:` が正しい数値なら、Preview 再生のテンポをその値に戻す（正しくない場合は表示のみ）。

### 16.6 フィール (`feel:` / `@feel:`)
- `straight` / `swing` / `shuffle` は記譜上の注記で、書かれた音価の拍数計算や Preview 再生のタイミングを変えない（8分音符2つは常に 8分音符2つ分）。
- `swing` / `shuffle` は `Swing` / `Shuffle` と表示する。`straight` は straight 以外からの変更の場合のみ `Straight` と表示する。

### 16.7 強弱・リハーサルマーク・テキスト
- `@dynamic:` は次の小節の強弱欄（段の下）に強弱記号を表示する。音量などの再生上の意味は持たない。
- `@mark:` は次の小節の上に四角で囲んだリハーサルマークを表示する。
- `@text:` は次の小節の上に演奏指示のテキストを表示する。

### 16.8 オッターヴァ (`@ottava:`)
- 音符の音高（`mel:`・小節内の音符）は常に実音で書く。`8va` の間は1オクターブ下の位置に、`8vb` の間は1オクターブ上の位置に符頭を描画し、`8va` / `8vb` の表示と破線で範囲を示す。`off` で通常に戻る。
- 保存されている音高（実音）は変わらない。実音移調（§4.5）は実音を移調する（`8va` 中の `c5` を +2 すると `d5` になり、`d4` の位置に描画される）。
- 段をまたいで有効な場合は、次の段の頭から続きを描画する（段・ページをまたいで1本の線を描かない）。

## 17. 再利用フラグメント (`let`)

リズム・音符の並びに名前を付け、小節セルや `mel:` セルから再利用する。

### 17.1 構文
```text
定義   := "let" 空白 識別子 "=" フラグメント
識別子 := [A-Za-z_][A-Za-z0-9_]*          （大文字・小文字を区別する）
参照   := "$" 識別子
フラグメント := 要素 ( 空白 要素 )*
要素   := リズムトークン（§8） | 音符（§12.2） | 休符（§12.2） | 同時複数音（§18） | 参照
```
```guitardsl
let basic8 = 8.d 8.u 4.d 8.d 8.u 4.d
let riff = e4/8 g a g
let picking = 8.d c4/8 e g 8.u
let chordHit = [c4,e4,g4]/4
let phrase = $riff [c4,e4,g4]/4
```
- 行頭（前の空白は可）が `let` と空白で始まる行はすべてフラグメント定義行として扱う。構文に合わない行（識別子・`=`・右辺の欠落、`let x: rhythm = …` のような型注釈など）はエラーとし、他の行の種類としては解析しない。
- 型注釈は書かない（V1 に型の構文はない）。1つの定義は1行に書く（複数行の定義はない）。
- 右辺の後ろの空白に続く `#` 以降はコメント（§2.3）。`f#4` のように空白の後でない `#` はコメントではない。
- 定義はファイル全体で有効（グローバル）で、使う位置より前でも後でもよく、セクションの間に書いてもよい。定義行は小節を作らず、セクション・ページ・メロディの割り当て位置（§12.3）を変えず、スコアイベントも作らない。
- 同じ名前の定義が複数あればエラーとし、最初の定義を使う。
- 引数付きの定義、再代入、セクション・ブロック単位の定義はない。ヘッダー・スコアイベントの値・コード定義・`lyr:` の中では参照できない。

### 17.2 参照と展開
- 小節行のセル、および `mel:` のセルの中で、トークンの位置に `$name` を書くと、その位置に定義の並びがそのまま入る（テキストの置換ではなく、解析済みの並びを複製して入れる）。参照先の定義の中の参照も展開する。
- 定義同士の参照が循環する場合はエラー。未定義の名前の参照はエラー（参照の位置に報告する）。エラーのある定義の参照は何も展開せず、同じエラーを参照ごとに繰り返し報告しない。
- 小節の長さの検証（§8、§12.3）は展開後の並びで、参照を含む小節・メロディのセルに対して行う。小節より短い定義は定義自体はエラーではない。
- 歌詞（§13）の音節の割り当て、装飾音符・接続・スラーの検証は展開後の並びに対して行う。
- コードだけのセルに続くセルが小節内で使える参照だけでも、§6.2 の形式B（コードセルとリズムセルの分割）として1小節にまとめる（`| C | $groove |` は `| C | 8.d 8.u 4.d 8.d 8.u 4.d |` と同じ）。

### 17.3 使える位置（文脈）
各要素が使える位置から、フラグメントが使える位置を決める（公開の型ではない）。

| 要素 | 使える位置 |
|---|---|
| リズムトークン（`8.d`、`r8` 等） | 小節行 |
| 音符（`e4/8`） | 小節行・`mel:` |
| 同時複数音 | 小節行・`mel:` |
| 休符（`r/8`、`r:1`） | `mel:` |
| 参照 | 参照先の定義が使える位置 |

- フラグメントが使える位置は、すべての要素が使える位置の共通部分とする。共通部分がない定義（`mel:` 専用の休符とリズムトークンの混在など）はエラー。
- 使えない位置での参照はエラー（参照の位置に報告する）。例: `let picking = 8.d c4/8 e g 8.u` は小節行専用で、`mel: | $picking |` はエラー。

### 17.4 継承の独立
- 定義の中の音符は、その定義だけでオクターブと長さを継承する（§12.2 の `mel:` 行と同じ規則）。定義の最初の音高を持つ単音はオクターブと長さを自分で書く（`let bad = e g` はエラー、`let ok = e4/8 g` は正しい）。先に休符や同時複数音があっても、その長さ・オクターブを受け取らない（`let bad = r/4 e4` はエラー、`let ok = r/4 e4/4` は正しい）。最初の単音が装飾音符の場合も同じで、その装飾音符がオクターブと長さを書く（`let bad = d4{grace} e4/4` はエラー、`let ok = d4/8{grace} e4/4` は正しい）。定義の中ではオクターブ 4 を既定値として補わない。
- 参照は、使う位置の直前の音符のオクターブ・長さを受け取らず、参照の後の音符にも自分の最後の状態を渡さない。`mel: | c5/4 $riff b |` の `b` は `c5/4` を継承する。定義の中の参照も同様に、囲む定義の継承状態を読まず・変えない。
- `%`（§8.7、§12.1）は定義の右辺には書けない（エラー）。`%` は小節・`mel:` のセルでの直前の小節の繰り返しの意味だけを持つ。

### 17.5 定義の境界
定義は、使う側に未完の状態を残さない。定義の中で書かれた次のものは、展開後の定義の中で完結しなければならない（完結しない場合はエラー）。
- `hammer` / `pull` / `slide` / `gliss` の接続先、およびタイ `~` の続く先。タイの直後は定義の中の音高を持つ単音でなければならない（定義の最後の音符のタイ、休符へのタイはエラー。同時複数音へのタイは §18.2 のとおりエラー）。
- 装飾音符（`grace`）の後の拍を持つ音符。
- `slur-start` と `slur-end` の対応。

参照の前に呼び出し側が書いた接続は、従来の規則（§12.2.1）どおり展開後の最初の音符を接続先にできる。

## 18. 同時複数音 (Note Groups)

同じ時点で鳴る複数の音を、1つの長さを共有する1つの音符として書く。

### 18.1 構文
```text
同時複数音 := "[" 構成音 "," 構成音 ( "," 構成音 )* "]" 長さ 奏法ブロック?
構成音     := 音名 臨時記号? オクターブ
```
```guitardsl
| C | [c4,e4,g4]/4 [c4,eb4,g4]/8 8.u 4.d [c4,e4,g4]/4{staccato} |
| C | G |
mel: | [c4,e4,g4]/2 [d4,f4,a4]/2 | [c4,e4,g4]/4. [d4,f4]/8 [e4,g4]/8{3:2} [e4,g4]/8{3:2} [e4,g4]/8{3:2} [c4,e4,g4]/4 |
```
- 構成音は2つ以上。各構成音はオクターブを必ず書く（継承しない）。音名は小文字のみ。同じ音高の重複はエラー。`[...]` の中に空白は書けない。
- `]` の後の長さ（§12.2 の `/` 音価または `:` 拍数、連符・複合音価を含む）は必須で、全構成音に共通。構成音ごとの長さ・奏法・タイは書けない。
- `mel:` の音符の位置と、小節行の音高付き音符の位置の両方に書ける。長さは1回だけ消費する（構成音の数だけ進まない）。
- 前後の音符のオクターブ・長さの継承には参加しない。
- 歌詞（§13）では1つの音符として1音節を取る。
- 独立した複数の声部（同じ時点で長さの違う音）は扱わない。
- `[Intro]` のような行全体のセクション見出し（§5）は同時複数音ではない。

### 18.2 奏法
- 付けられる奏法: `vibrato` `staccato` `tenuto` `fermata` `breath` `grace` `pm` `let-ring`。`grace` の同時複数音は拍数 0（§12.2.1）。
- `hammer` `pull` `slide` `gliss` `bend:` `slur-start` `slur-end` とタイ `~` は、どの構成音に対するものか決まらないため、同時複数音にはエラーとする。
- 単音の `hammer` / `pull` / `slide` / `gliss` の接続先（次に鳴る音符）が同時複数音の場合はエラー（構成音を選ばない）。単音から同時複数音へのタイもエラー。

### 18.3 描画
- 1つの横位置に全構成音の符頭を描き、符幹・旗・連桁は1つを共有する（連桁のまとまりでは1つの音符として扱う）。同時複数音の符幹の向きは連桁によって変えない。`mel:` の連桁のまとまりに向きの異なる同時複数音がある場合は、その位置で連桁を分ける。同時複数音と同じ連桁に入る単音は、その同時複数音の向きにそろえる。
- 符幹の向きは、第3線（B4）から最も遠い構成音で決める（上にある場合は下向き、下にある場合は上向き。距離が等しい場合は下向き）。
- 2度（隣り合う位置）でぶつかる符頭は、慣例どおり符幹の反対側へ交互に1つ分ずらす。加線は全構成音に必要な範囲を1本ずつ描く（重ねて描かない）。
- 臨時記号は構成音ごとに判定し、縦に重なる場合は左へ列をずらして並べる。`mel:` の同時複数音は §12.4 の調号と小節内の状態で判定する。小節行の同時複数音は、小節行の単音と同じく変化記号付きの音高にだけ描く。
- 複合音価は分割した各音符に同じ同時複数音を描き、各構成音をタイでつなぐ。
- 奏法記号は外側の符頭・共有の符幹を基準に置く。
- 小節行の同時複数音: 符幹が上向きの場合は小節行の単音と同じくスラッシュと共通の連桁に加わる。下向きの場合は連桁に加わらず、下向きの符幹と旗で描く（その位置で連桁のまとまりを分ける）。
