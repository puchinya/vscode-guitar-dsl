# GuitarDSL 言語構文仕様書 (GuitarDSL Syntax Specification)

本書は、ギター弾き語りおよびアコースティックギターストローク譜向けドメイン特化言語 **GuitarDSL** の言語構文、字句規則、およびレンダリング仕様を定義する規範的仕様書（Normative Public Contract）である。

---

## 1. 概要 (Overview)

GuitarDSL は、五線譜・リズムスラッシュ・ピッキング記号（ダウン／アップ）・コードネーム・コードダイアグラム・歌詞から構成されるポピュラー音楽向けリズム譜を、テキストベースで平易に記述するためのDSLである。

- **ファイル拡張子**: `.guitardsl`, `.gdsl`
- **文字エンコーディング**: UTF-8
- **言語種別**: 行指向の宣言的テキストフォーマット

---

## 2. 字句構造 (Lexical Structure)

### 2.1 行指向性
GuitarDSL は行単位で解析される。1行は原則として以下のいずれかの要素を表す。
1. 空行
2. コメント行
3. メタデータヘッダー行
4. セクション見出し行
5. 小節行
6. 改ページ行 (Page Break)
7. メロディ行 (`mel:`、§12)
8. 音節歌詞行 (`lyr:`、§13)
9. コード定義行 (`chord`、§7.4)

### 2.2 空行および空白文字
- 空行（改行のみ、または空白文字のみの行）は無視される。
- トークンを区切る連続した半角空白およびタブ文字は、単一の区切り文字として扱われる。

### 2.3 コメント
- ハッシュ記号 `#` から行末まではコメントとして扱われ、構文解析時に無視される。
- 行頭からのコメントおよび行末コメントの双方が有効である。

```guitardsl
# これは行全体のコメントです
key: C # 行末コメント
```

---

## 3. ドキュメント構成 (Document Structure)

GuitarDSL ドキュメントは通常、以下の順序で構成される。

1. **ヘッダー部**: 楽曲のタイトル、アーティスト、キー、テンポ、カポ位置などのメタデータ
2. **スコア部**: セクション見出しおよび小節行からなる楽譜本体

---

## 4. メタデータヘッダー (Metadata Headers)

メタデータヘッダーは、楽曲全体の属性を定義する。

### 4.1 構文
```text
<key>: <value>
```
- キー名は大文字・小文字を区別しない（Case-insensitive）。
- コロン `:` の前後の空白はトリムされる。

### 4.2 サポートされるヘッダーキー一覧

| キー名 | 別名 | 説明 | デフォルト値 | 描画位置・役割 |
|---|---|---|---|---|
| `title` | - | 楽曲タイトル | `Guitar Rhythm Score` | ヘッダー最上部に大見出しで表示 |
| `artist` | - | アーティスト名／作詞・作曲者 | (空) | タイトル直下に `Words & Music: <artist>` として表示 |
| `capo` | - | カポタストの位置（フレット数） | `0` | 右上部に `Capo: <capo>` バッジとして表示 |
| `key` | `original_key` | 楽曲のキー（調） | `C` | 右上部に `Key: <key>` として表示 |
| `bpm` | `tempo` | テンポ（拍/分） | `90` | 右上部に `BPM: <bpm>` として表示 |
| `memo` | - | 演奏上の注意・メモ | (空) | ドキュメント内のメタ情報（将来拡張用） |
| `style_chord_size` | `chord_size` | コードネームの文字サイズ | `15px` | コードネームのフォントサイズ |
| `style_lyric_size` | `lyric_size` | 歌詞テキストの文字サイズ | `10px` | 五線下の歌詞フォントサイズ |
| `style_title_size` | `title_size` | タイトルの文字サイズ | `20pt` | 楽曲タイトルのフォントサイズ |
| `style_section_size` | `section_size` | セクションラベルの文字サイズ | `9.5px` | [Intro] 等の枠内フォントサイズ |
| `style_font_size` | `font_size`, `text_size` | 全体の基準フォントサイズ | `10pt` | 全体の基本フォントサイズ |
| `show_rhythm` | `rhythm` | リズム譜表の表示（`true` / `false`、`on` / `off`） | `true` | `false` でリードシートモード（§14.2） |
| `measures_per_row` | `bars_per_row` | 1段あたりの小節数（1〜8の整数） | `4` | 段の折り返し（§11）。範囲外・不正値は警告しデフォルト |

### 4.3 記述例
```guitardsl
title: 風のコンパス - Wind Compass
artist: GuitarDSL Original
capo: 0
key: C
bpm: 104
memo: 軽快な8ビートストローク。
```

### 4.4 カポとコード名の意味論
- `capo` は物理的なカポタストの位置（フレット数）を表す。ヘッダーを省略した場合はカポ 0 とみなす。カポ変更・推論（拡張機能 §4B / §4.4）が扱う値は 0〜12 の整数に限る。それ以外の値（`capo: x`、`capo: 13` など）は表示上そのまま扱われるが、カポ変更の対象外となる。
- 小節に書かれたコード名は、カポを基準に**押さえるフォーム（シェイプ）**を表す。実際に鳴る音はコード名をカポのフレット数だけ上げたものになる（例: `capo: 2` の `A` は B の響き）。
- `key` / `original_key` は**実際に鳴る調**を表す。カポの位置によって変わらない。
- メロディ（`mel:` 行・小節内の音符）は実音で記譜する。カポの位置によって変わらない。
- 鳴る響きを保ったままカポを `sourceCapo` から `targetCapo` に変える場合、書かれたコード名のルートとスラッシュのベース音を `targetCapo - sourceCapo` 半音だけ下げて書き直す。音名の綴りは `C, C#, D, Eb, E, F, F#, G, Ab, A, Bb, B` を使う。コードの種類（`m7` などのサフィックス）、長さの指定（`:2`、`/4.`）、`key`、メロディ、リズム、歌詞、BPM、セクション、繰り返し、コメント、改ページ、スタイルは変えない。
  - 例: `capo: 0` の `B` → `capo: 2` の `A`、`F#m` → `Em`、`E/G#` → `D/F#`。`capo: 3` の `C` → `capo: 5` の `Bb`。
- 弾きやすさ（難易度）は DSL に保存しない。`difficulty:` のようなヘッダーは定義しない。

## 5. セクション見出し (Section Headers)

楽曲の構造（Intro、Aメロ、サビなど）を示す見出しラベルを定義する。

### 5.1 構文
```text
[<セクション名>]
```
- 行頭が `[` で始まり、行末が `]` で終わる行がセクション見出しとして認識される。
- セクション名には英数字、記号、日本語（ひらがな・カタカナ・漢字等）を含む任意の文字列が使用可能。

### 5.2 振る舞い
- セクション見出しが定義されると、その直後に出現する**先頭の小節の上部**に、四角い枠線で囲まれたセクションボックスとして描画される。
- 1つのセクション指定は1回のみ消費され、後続の小節には引き継がれない。

### 5.3 記述例
```guitardsl
[Intro]
| C | 4.d 4.d 4.d 4.d |

[サビ]
| F | 8.d 8.u 4.d 8.d 8.u 4.d |
```

## 6. 小節行と小節線 (Measures and Barlines)

楽譜の小節および小節線（小節区切り）を定義する。行内にパイプ記号 `|` が含まれる場合、小節行として解析される。

### 6.1 小節線記号 (Barlines)

| 記号 | 名称 | 説明・描画 |
|---|---|---|
| `\|` | 通常小節線 | 1本の細い縦線で小節を区切る。 |
| `\|:` | リピート開始線 | 左側に太線、右側に細線、および2つのリピートドットを描画。 |
| `:\|` | リピート終了線 | 左側に2つのリピートドット、細線、右側に太線を描画。 |

### 6.2 小節の記述形式

小節は以下のいずれかの形式で記述できる。

#### 形式A: 1小節内にコードとリズムを併記
```guitardsl
| C 4.d 4.d 4.d 4.d | G 4.d 4.d 4.d 4.d |
```

#### 形式B: コードセルとリズムセルを分割（推奨可読形式）
```guitardsl
| C  | 4.d 4.d 4.d 4.d |
| G  | 4.d 4.d 4.d 4.d |
```
- パーサーは、「コードのみを含むセル」の直後に「リズムのみを含むセル」が存在する場合、それらを単一の小節データとして自動結合（マージ）する。

#### 形式C: リピート記号を含む小節
```guitardsl
|: C | 4.d 4.d 4.d 4.d |
|  F | 4.d 4.d 4.d 4.d :|
```

## 7. コード表記 (Chords)

各小節で演奏するギターの和音（コードネーム）を指定する。

### 7.1 構文規則
コードトークンは以下の正規表現パターンに合致する文字列である。

```regex
^[A-G][b#]?(maj|m|min|aug|dim|sus[24]|add9|[0-9]+)*(\/[A-G][b#]?)?$
```

- **ルート音**: `A` 〜 `G`（必要に応じて半音下げ `b` または半音上げ `#`）
- **コードクオリティ / テンション**:
  - メジャー / マイナー: `m`, `min`, `maj`
  - サスペンデッド: `sus2`, `sus4`
  - オーグメント / ディミニッシュ: `aug`, `dim`
  - セブンス / ナインス / テンション: `7`, `maj7`, `m7`, `add9` 等
- **オンコード（分数コード）**: スラッシュ記号 `/` に続けてベース音を指定（例: `G/B`, `D/F#`）
- **ダイアグラムの指定（任意）**: コード名の直後に `@<ラベル>` を付けると、§7.4 で定義したその押さえ方のダイアグラムを使う（例: `C@barre`）。ラベルは英数字と `_`（`[A-Za-z0-9_]+`）。長さを付けるときはラベルの後に書く（`C@barre:2`、`G/B@alt/2`）。五線譜上では、コード名の右上にラベルを小さい灰色の上付き文字で添える（リズム段・メロディ段とも。同じコード名の押さえ方が1種類しかなくても表示する）。

### 7.2 1小節内の複数コードチェンジ (Multiple Chords per Measure)
1小節内で2回以上のコードチェンジを行う場合、以下の記法をサポートする。

#### 1. 形式B（セル分割形式・均等配分）
コードセルに複数のコードを半角空白区切りで並べる。
```guitardsl
| C G | 8.d 8.u 4.d 8.d 8.u 4.d |
```
- 目印（拍指定）のない場合、小節の拍数に応じて均等に配分される（4/4拍子で2コードの場合、0拍目から2拍分が `C`、2拍目から2拍分が `G` となる）。

#### 2. 形式B（セル分割形式・長さ指定）
不均等なコードチェンジ（例: 3拍＋1拍）や、シンコペーションによるコードチェンジ（例: 2拍目の裏でチェンジ）を行う場合、コードの直後に長さを付与する。長さは次の2通りで書ける（1小節内で混在してよい）。

| 区切り | 意味 | 例 |
|---|---|---|
| `:` | **拍数**（4分音符 = 1、小数可） | `C:2.5 G:1.5`、`C:3 G:1` |
| `/` | **音価**（§8.2.1 共通音価表記） | `C/2+8 G/4.`、`C/2. G/4` |

```guitardsl
| C:3 G:1       | 4.d 4.d 4.d 4.d |
| C/2+8 G/4.    | 4.d 8.d 8.u.a 8.u 8.d 8.d 8.u |
| G/B/2 D/F#/2  | 4.d 4.d 4.d 4.d |
```
- 分数コードのベース音指定（`/B`）と音価（`/2`）は、`/` の直後が英字（ベース音）か数字（音価）かで区別する。分数コードに長さを付ける場合はベース音の後に続ける（`G/B/2`、`G/B:2`）。
- 長さ指定のないコードは 2 拍として扱う。
- 長さとして不正な値はエラー診断となり、その小節のコードは均等配分で配置される。

#### 3. 形式A（インライン形式）
リズムトークンの間にコードを直接記述する。
```guitardsl
| C 4.d 4.d G 4.d 4.d |
| C 4.d 8.d G 8.u 4.d 8.d 8.u |
```
- リズムの累積拍位置に応じて、各コードが配置されたタイミングでコードチェンジが行われる。

### 7.3 コードダイアグラム (Chord Diagrams)
スコア内で一度でも使用されたコードは自動的に収集され、楽譜上部のダイアグラム領域にフレット指板図として一覧描画される（小節内に複数コードがある場合もすべて網羅される）。

- 収集の単位は「コード名 + ラベル」である。`C` と `C@barre` を両方使うと、ダイアグラムは2枚描かれる。並び順は最初に使われた順。
- 各ダイアグラムの押さえ方は、次の順に決まる。
  1. ファイル内にある、そのキー（`C@barre` なら `C@barre`）の `chord` 定義（§7.4）
  2. ラベル付きで該当する定義がない場合は、ラベルなしの定義（`C`）
  3. 組み込みのプリセットライブラリ（下記）の既定の押さえ方
  4. どれにも当てはまらない場合は、既定のフォールバック形状（`xx0232`）
- 組み込みプリセットライブラリ:
  - 手書きの基本形（既定の押さえ方として優先する）: `C`, `G`, `D`, `A`, `E`, `F`, `Am`, `Em`, `Dm`, `B7`, `Dm7`, `Am7`, `Em7`, `G7`, `C7`, `A7`, `E7`, `Bm7`, `Fmaj7`, `Cmaj7`, `Cadd9`, `G/B`, `D/F#`
  - 12 のルート（`C C# D Eb E F F# G Ab A Bb B`）× 15 のタイプ（`maj m 7 maj7 m7 sus2 sus4 7sus4 6 m6 add9 9 m9 dim aug`）について、移動できる形（E 型・A 型・D 型・C 型・G 型）をルートに合わせて平行移動した押さえ方。15 フレットを超えるもの、押弦の幅が 5 フレットを超えるものは含めない。
  - 上記以外のコード名（ルートの異名同音 `D#` 等は同じピッチとして扱う。`min` は `m` と同じ）はフォールバック形状になる。分数コードは手書きの基本形にあるものだけがライブラリで解決される。
- ダイアグラムの描画内容:
  - 6 本の弦と 5 フレット分の枠。ミュート弦の `×`、開放弦の `○`、押弦位置の黒丸。
  - 開始フレットが 1 のときは太いナットを描く。2 以上のときはナットを細線にして、枠の左に開始フレット番号を描く。
  - セーハ（`barre`）は、対象の弦の範囲をまたぐ角丸のバーで描く。
  - 指番号（`fingers`）があれば、枠の下に各弦の指番号を描く。
  - コード名の下に、ラベルを小さい灰色の文字で描く（ラベル付きのダイアグラムのみ）。五線譜上の上付きラベル（§7.1）と同じ文字列なので、どのダイアグラムを使うか対応が取れる。
  - プリセットライブラリの押さえ方には、押弦が 5 本以上あり開放弦を使わない場合、最低フレットにセーハを付ける。

### 7.4 コード定義 (Chord Definitions)
ダイアグラムの押さえ方をファイル内で定義する。同じコード名に `@ラベル` を付けて、押さえ方を何通りでも定義できる。

#### 7.4.1 構文
```text
chord <コード名>[@<ラベル>] = <フレット> [base:<n>] [fingers:<指番号>] [barre:<フレット>[:<弦>-<弦>]]...
```
- 行頭の `chord` の後に空白が続く行をコード定義行とする（大文字・小文字を区別しない）。ファイル内のどこに書いてもよいが、通常はヘッダー部に書く。
- `<コード名>` は §7.1 の構文に従う。`<ラベル>` は `[A-Za-z0-9_]+`。ラベルのない定義が、そのコード名の既定の押さえ方になる。
- `<フレット>` は 6 弦から 1 弦の順に 6 つ書く。
  - すべて 1 桁のときは続けて書ける（`x32010`）。2 桁のフレットがあるときはカンマで区切る（`x,x,10,9,8,8`）。
  - `x` はミュート、`0` または `o` は開放弦、数値は**絶対フレット**（0〜24）。
- オプション（順不同。`barre` は複数書ける）:

| オプション | 値 | 意味 |
|---|---|---|
| `base:<n>` | 1〜24 | 図の開始フレット。省略すると自動で決める（押弦の最高フレットが 5 以下なら 1、そうでなければ押弦の最低フレット） |
| `fingers:<6文字>` | `-`、`1`〜`4`、`T` | 6 弦から 1 弦の順の指番号。`-` は指番号なし、`T` は親指 |
| `barre:<f>` | フレット | フレット `<f>` のセーハ。範囲は、そのフレットを押さえている最低弦から最高弦まで |
| `barre:<f>:<a>-<b>` | フレット、弦番号 1〜6 | 弦 `<a>` から `<b>` までのセーハ（例: `barre:3:5-1`） |

- 行末コメント（空白の後の `#` 以降）は無視する。`C#` のように音名に続く `#` はコメントではない。

#### 7.4.2 参照と解決
- 小節内のコードトークン `<コード名>@<ラベル>` で、その定義を参照する（§7.1）。
- ラベルのない `<コード名>` は、ラベルのない定義があればそれを、なければプリセットライブラリを使う（§7.3）。
- 定義の位置と参照の位置の前後関係は問わない。

#### 7.4.3 診断
| コード | 重大度 | 条件 | 振る舞い |
|---|---|---|---|
| `invalidChordDefinition` | エラー | 構文、コード名、ラベル、フレット、オプションの値が不正。または押弦位置（セーハを含む）が開始フレットから 5 フレットの範囲に収まらない | その行を無視する |
| `duplicateChordDefinition` | 警告 | 同じ `コード名@ラベル`（ラベルなし同士を含む）の定義が 2 回以上ある | 最初の定義を使う |
| `unknownChordVariant` | 警告 | 参照 `C@x` に対応する定義がない | ラベルのない `C` の解決結果で描く |

#### 7.4.4 記述例
```guitardsl
title: Voicing Sample
chord C       = x32010
chord C@barre = x35553 fingers:-13331 barre:3
chord C@high  = x,x,10,9,8,8 fingers:--4312

[Intro]
| C | 4.d 4.d 4.d 4.d |
| C@barre:2 C@high:2 | 4.d 4.d 4.d 4.d |
```

## 8. リズム・ストローク記法 (Rhythm and Stroke Tokens)

各小節内のストロークパターン、ピッキング方向、アクセント、音価を定義する。

### 8.1 トークン書式
```text
<音価>[.<修飾子1>.<修飾子2>...]
```
ドット `.` で区切ることで、音価に対して複数の修飾子（ピッキング方向、表現など）を付与する。

### 8.2 音価 (Duration)

| 指定値 | 名称 | 楽譜上での意味・描画表現 |
|---|---|---|
| `1` または `w` | 全音符 (Whole note) | 4拍分の長さ。幅広の白抜きスラッシュヘッド（符幹なし）として小節中央に描画 |
| `2` または `h` | 2分音符 (Half note) | 2拍分の長さ。白抜きのスラッシュヘッド＋符幹として描画 |
| `4` または `q` | 4分音符 (Quarter note) | 1拍分の長さ。黒塗りのスラッシュヘッド＋符幹として描画 |
| `8` | 8分音符 (Eighth note) | 1/2拍分の長さ。黒塗りスラッシュヘッド＋符幹。同拍内の音符とは太い連桁（ビーム）で結線（孤立時は旗） |
| `16` | 16分音符 (Sixteenth note) | 1/4拍分の長さ。黒塗りスラッシュヘッド＋符幹。同拍内の音符とは二重連桁（ビーム）で結線（孤立時は二重旗） |
| `8t` `4t` `16t` | 3連符 | 基本音価の 2/3 の長さ。拍単位でグループ化し括弧＋「3」を描画 |
| `4+8` 等 | 加算 | 各項の和の長さ。項ごとのスラッシュをタイで結んで描画 |

リズムトークンでは `.` が修飾子区切りであるため、付点は加算で表す（付点4分 = `4+8.d`）。

#### 8.2.1 共通音価表記 (Note Value Notation)
コードの長さ指定の `/` 形式（§7.2）、メロディ音符の `/` 形式（§12）で共通に用いる音価表記を以下に定める。リズムトークン（§8.2）も付点 `.` を除き同じ規則に従う。

```text
音価     := 項 ( "+" 項 )*
項       := 基本音価 ( "." | "t" )?
基本音価 := "1" | "2" | "4" | "8" | "16"
```

| 表記 | 意味 | 拍数（4分音符 = 1） |
|---|---|---|
| `1` `2` `4` `8` `16` | 全・2分・4分・8分・16分音符 | 4, 2, 1, 1/2, 1/4 |
| `2.` `4.` `8.` | 付点（1.5 倍） | 3, 3/2, 3/4 |
| `4t` `8t` `16t` | 3連符（2/3 倍） | 2/3, 1/3, 1/6 |
| `2+8` | 加算 | 5/2 |

- 拍数の合計は有理数として厳密に扱う（`8t` ×3 = 1 拍）。
- 小節の合計が 4 拍と一致しない場合は警告診断となる（描画は継続）。

### 8.3 休符 (Rest)
- 音価の先頭に `r` を付与することで休符となる（例: `r1`, `rw`, `r2`, `rh`, `r4`, `rq`, `r8`, `r16`）。
- 楽譜上には音価別のベクター休符記号（全休符: 第4線吊り下げ、2分休符: 第3線上、4分休符、8分休符、16分休符）として描画され、スラッシュヘッドやピッキング記号は描画されない。

### 8.4 修飾子 (Modifiers)

| 修飾子 | 完全名 | 名称 | 描画・効果 |
|---|---|---|---|
| `d` | - | ダウンストローク | スラッシュ上部にダウンピッキング記号（`п`）を描画 |
| `u` | - | アップストローク | スラッシュ上部にアップピッキング記号（`∨`）を描画 |
| `g` | `ghost` | ゴーストノート | ブラッシング／ミュートストローク。透明度35%で薄く描画 |
| `a` | `accent` | アクセント | スラッシュ上部にアクセント記号（`>`）を描画 |
| `t` | `tie` | タイ | 音を伸ばすタイ属性（後続音との連結情報） |

### 8.5 記述例
- `4.d`: 4分音符のダウンストローク
- `8.u`: 8分音符のアップストローク
- `16.d.a`: 16分音符のダウンストローク（アクセント付き）
- `8.d.g` または `8.d.ghost`: 8分音符のダウングーストノート（ブラッシング）
- `1.d`: 1小節伸ばす全音符ダウンストローク

### 8.6 リズム省略時のデフォルト補完
小節内にリズムトークンが1つも指定されていない場合、パーサーは自動的に以下のデフォルトリズム（4分音符4拍）を補完する。
- 1拍目: `4.d`（4分音符ダウンストローク）
- 2拍目: `4`（4分音符ストローク方向なし）
- 3拍目: `4.d`（4分音符ダウンストローク）
- 4拍目: `4`（4分音符ストローク方向なし）

### 8.7 小節の繰り返し記号 (Measure Repeat Sign / Simile Mark)
前小節のリズムパターンをそのまま繰り返すことを示す記号として、パーセント記号 `%` を使用できる。

- **記法**:
  - **形式B（セル分割形式）**:
    ```guitardsl
    | Am Em | % l:"あたらしいドアを ひらく" |
    ```
  - **形式A（インライン形式）**:
    ```guitardsl
    | Am Em % l:"あたらしいドアを ひらく" |
    ```
  - **コード省略**:
    ```guitardsl
    | % l:"歌詞テキスト" |
    | % |
    ```
    コードセルまたはコード指定を省略した場合は、直前小節のコード（単一または複数）がそのまま自動的に引き継がれる。
- **振る舞い・描画**:
  - 五線譜の中央（第3線を中心）に、太い斜線と上下2つのドットからなる標準的なメジャーリピート記号（`%`）が描画される。
  - 当該小節の通常のスラッシュ符頭、符幹、連桁、ピッキング記号、アクセントは非表示となる。
  - 小節に指定されたコードネーム（単一または複数）は上部に、歌詞テキストは下部に通常通り描画される。

### 8.8 反復記号・小節線・演奏順序記号

#### 反復小節線 (Repeat Barlines)
- `|:`: 反復開始線（左側に太線＋細線＋2つのドット）
- `:|`: 反復終了線（右側に2つのドット＋細線＋太線）
- `|::|`: 連続する反復線

#### 1番・2番カッコ (Volta Brackets)
- `[1.]`, `[2.]`, `[1,2.]`, `[1-2.]`: 小節内に記述することで、その小節の上部にカギ線（ブラケット）と番号を描画する。
  - `:|` と併用された終了小節では右端の縦フックが閉じられる。
  - 例: `|: C G | [1.] Am Em :| [2.] F G ||`

#### 複縦線・終止線 (Double and Final Barlines)
- `||`: 複縦線（セクションの区切り等。細線2本）
- `|]`: 終止線（楽曲の終了。細線＋太線）

#### 演奏順序記号 (Navigation / Jump Marks)
- `Fine`, `D.C.`, `D.S.`, `Coda`, `to Coda`, `Segno`: 小節内に記述することで、小節上部に演奏指示記号を描画する。
  - `Segno`: 𝄋
  - `Coda` / `to Coda`: 𝄌
  - `Fine`: *Fine*
  - `D.C.`: *D.C.*
  - `D.S.`: *D.S.*

## 9. 歌詞記法 (Lyrics)

小節内の該当位置に対応する歌詞テキストを指定する。

### 9.1 構文
```text
l:"<歌詞テキスト>"
```
または
```text
~"<歌詞テキスト>"
```
- ダブルクォート `"` で囲まれた文字列が歌詞として抽出される。
- 小節内の任意の位置（通常は小節末尾）に記述可能。

### 9.2 描画
- 当該小節の五線譜最下線の真下（中央揃え）に歌詞テキストとしてレンダリングされる。
- メロディ（§12）が割り当てられた小節では、音符単位の歌詞（§13）を用いる。同一小節に `l:"..."` とメロディが両方ある場合は警告診断となり、`l:"..."` は描画されない。メロディのない小節では従来通り `l:"..."` を用いる。

### 9.3 記述例
```guitardsl
| C | 8.d 16.d 16.u 8.d 8.u 4.d l:"あさのひかりを あびながら" |
```

## 10. 改ページ記法 (Page Breaks)

楽譜内の明示的なページ区切り（改ページ）を定義する。

### 10.1 構文
```text
---
```
または
```text
pagebreak
```
- 行頭から行末までが3文字以上のハイフン `---`（または `-` の連続）、あるいはキーワード `pagebreak`（大文字・小文字不問）のみで構成される行が改ページ行として認識される。
- 前後に任意の半角空白またはタブが含まれていてもよい。

### 10.2 振る舞い
- コンパイラは改ページ行を検出すると、後続の小節行やセクション見出しを新しいページ（`ScorePage`）としてグループ化する。
- 1ページ目にはフルヘッダー（曲名、アーティスト、キー、テンポ、カポ、コードダイアグラム）が描画される。
- 2ページ目以降の先頭には、曲名とページ番号（例: `風のコンパス - p. 2`）からなるランニングヘッダーがコンパクトに描画される。

## 11. レンダリング・レイアウト仕様 (Rendering and Layout Rules)

GuitarDSL コンパイラが生成する SVG / HTML 楽譜の表示規則は以下の通りである。

1. **システム（段）構成**:
   - 各ページ内の小節は**1段あたり `measures_per_row` 小節（デフォルト4）**で自動的に折り返される。改ページが行われると、次の小節は新しいページの第1段先頭に配置される。
   - 各段の全幅は 780px、各小節は均等に割り振られる。
   - メロディのない小節では、小節内の各リズム符（スラッシュ・休符）は等間隔（Equal Spacing）で配置される。
   - メロディのある小節では、リズム符とメロディ音符の発音拍の和集合を列として等間隔に並べ、メロディ譜表とリズム譜表の同じ拍を縦に揃える。
   - 段の高さはメロディの有無・歌詞の番数・`show_rhythm` により段ごとに決まる。メロディのない段の高さは従来通り（段座標 140）。
2. **段頭の記号**:
   - すべての段の先頭に五線とト音記号（Treble Clef）が描画される。
   - メロディ譜表では、ト音記号の直後に調号（§14.1）が描画される。
   - 第1段のト音記号（調号がある場合は調号）直後にのみ、4/4 拍子記号が表示される。
3. **垂直レイアウト順（メロディのない段、上から下）**:
   1. セクション名（`[Intro]` 等の枠付きラベル: y=6〜22）
   2. コードネーム（太字テキスト: baseline y=32）
   3. アクセント記号（`>`: y=38〜44）
   4. ピッキング記号（`п`, `∨`: y=47〜52）
   5. 連桁・符幹（Beams / Stems: y=60〜79）
   6. 五線譜（Stave Lines: 5本線 y=70, 78, 86, 94, 102）およびリズムスラッシュヘッド（第3線 y=86 を中心に配置、全音符・2分音符は白抜き、4分音符以下は黒塗り）
   7. 歌詞テキスト（五線下部 y=120）

   メロディのある段（上から下）: セクション名 → コードネーム → メロディ譜表（加線・臨時記号を含む）→ 音符単位の歌詞（番数分）→ リズム譜表（上記 3〜7 と同じ構成）。`show_rhythm: false` の場合はリズム譜表を省略する（§14.2）。
4. **プレビュー表示モード (Preview Display Modes)**:
   - プレビュー画面上部に固定ツールバー（Toolbar）が提供され、以下の表示方法をいつでも切り替え可能:
     - **1ページ表示（デフォルト）**: Wordの印刷レイアウトやPDFリーダーのように、選択した用紙枠が縦に並び、自然に縦スクロールして閲覧できる表示。
     - **見開き表示**: 見開き2ページを左右横並びで表示し、縦スクロール可能。
     - **Web表示（シームレス）**: 用紙枠や改ページ余白、ページ番号等の用紙概念を排除し、全小節が下までシームレスに続く表示。改ページ記法 `---` の位置には控えめな細い点線（`Page Break`）を表示。
5. **用紙設定と見開きPDF保存**:
   - ツールバーにて用紙サイズ（A3 / A4 [標準] / A5 / B4 / B5 / Letter）および向き（縦向き / 横向き）を選択可能。
   - 横向き（Landscape）選択時は、1枚の横向き用紙に2ページ（見開き）を割り付けた見開きPDF（2-up Spread Print）として出力される。
6. **PDF保存機能**:
   - ツールバーの「PDF保存」ボタンから、指定した用紙サイズ・向きで高品質なベクトルPDFを直接生成・保存できる。
   - 印刷機能は非対応（PDF保存に一本化）。

## 12. メロディライン (Melody Line)

小節行とは別に、歌のメロディ（音高と音価）を記述する。

### 12.1 構文
```text
mel: | <音符> <音符> ... | <音符> ... |
```
- 行頭が `mel:` の行をメロディ行とする。`|` で区切られた各セルが1小節分のメロディである。
- セル `%` は直前の小節のメロディを複製する（歌詞は複製しない）。直前の小節にメロディがない場合はエラー。

### 12.2 音符トークン
```text
音符 := 音名 臨時記号? オクターブ? 長さ? "~"?
休符 := "r" 長さ?
長さ := "/" 音価 | ":" 拍数           （音価は §8.2.1、拍数は 4分音符 = 1 の数値）
音名 := "a" | "b" | "c" | "d" | "e" | "f" | "g"     （小文字のみ）
臨時記号 := "#" | "b"
オクターブ := 0〜9 の数字（科学的音高表記、c4 = 中央ハ）
```
- 例: `e4/8`（E4 の8分音符）、`f#4/4`、`bb3/2`（B♭3 の2分音符）、`a4/4.`（付点4分）、`b4/8t`（8分3連）、`g4/2~`（次の音符へタイ）、`r/8`（8分休符）。拍数でも書ける（`e4:0.5` = `e4/8`）。
- 長さは、コードと同じく `/` の音価（§8.2.1）または `:` の拍数で書く。メロディの `:` 拍数は 1/4 拍の倍数に限る（描画時に付点・タイで音符に分解する）。3連符は `/` の音価（`8t` 等）で書く。
- **継承**: オクターブと長さを省略すると、同じ `mel:` 行内の直前の音符の値を引き継ぐ。各 `mel:` 行の最初の音符ではオクターブと長さを省略できない（エラー）。休符はオクターブを持たない。
- 大文字の音名はエラー（コードネームとの区別のため）。
- 音高は実音（歌のピッチ）で記述し、ト音記号の譜表に描画する。調号があっても常に実際の音高を書く（D メジャーでも `f#4`）。

### 12.3 小節への割り当て
- `mel:` 行の各セルは、**まだメロディが割り当てられていない最も前の小節**から順に割り当てられる。したがって、小節行1行ごとに `mel:` を書いても、複数小節の後にまとめて書いてもよい。
- セクション見出しおよび改ページを越えて割り当てることはない（それ以前の未割り当て小節はメロディなしとなる）。
- セル数が未割り当て小節数を超える場合、超過分はエラー。
- メロディが割り当てられない小節はメロディなしとして描画される。
- 小節内の合計が 4 拍と一致しない場合は警告。

### 12.4 描画
- 符頭（全・2分は白抜き、4分以下は黒塗り）、加線、付点、符幹（B4 より下は上向き、B4 以上は下向き）、拍単位の連桁、旗、休符、タイ（段をまたぐ場合は段末までの弧）、3連符の括弧と「3」を描画する。
- 臨時記号は調号（§14.1）と小節内の状態から必要な場合のみ描画する。小節内では持続し、小節線でリセットされる。調号や直前の臨時記号を打ち消す場合はナチュラルを描画する。タイで持ち越した音符には描画しない。

### 12.5 記述例
```guitardsl
| C  | 8.d 8.u 4.d 8.d 8.u 4.d |
| G  | % |
mel: | r/8 e4/8 e g a g e d | d4/8 d e d c/4 r/4 |
lyr: | あさの ひかりを      | あびなが ら         |
```

## 13. 音符単位の歌詞 (Syllable Lyrics)

### 13.1 構文
```text
lyr: <音節> <音節> ... [| ...]
```
- 行頭が `lyr:` の行を音節歌詞行とする。直前の `mel:` 行が割り当てた音符列に対応する。
- 1つの `mel:` 行の後に続く n 行目の `lyr:` 行が n 番の歌詞となる。
- `mel:` 行より前に現れた `lyr:` 行はエラー。

### 13.2 音節の割り当て
- 休符とタイの継続側の音符を除いた音符に、先頭から順に1音節ずつ割り当てる。
- 日本語（かな・漢字等）は1文字を1音節とする。ただし小書き文字 `ゃゅょぁぃぅぇぉゎ`（カタカナも同様）は直前の文字と結合する。`っ` `ー` は独立した1音節とする。
- 英数字は空白で区切られた単位を1音節とする。音節末尾の `-` は同一単語の続きを示し（例: `sun- shine`）、音節間にハイフンを描画する。
- `(ひか)` のように括弧で囲んだ文字列は1音節として扱う。
- `_` は直前の音節の延長（メリスマ）で、その音符には延長線を描画する。
- `*` は歌詞なしで1音符を飛ばす。
- `|` は任意。記述した場合は小節の境界と照合し、ずれていれば警告。
- 音節が音符より多い・少ない場合は警告（不足した音符は歌詞なし）。

### 13.3 描画
- 各音節は対応する符頭の x 座標に中央揃えで、メロディ譜表の下に描画する。複数番は上から 1番, 2番, … の順に行を重ねる。

## 14. 調号・表示設定 (Key Signature and Display Options)

### 14.1 調号
- `key:` ヘッダーの値から調号を決定する。書式は `<ルート>[b|#][m]`（例: `C`, `G`, `Bb`, `F#m`, `Am`）。メジャーは `C`〜`C#`、`Cb`、マイナーは対応する平行調（♯・♭ 最大7個）。
- 解析できない値の場合は調号なし（ヘッダーのテキスト表示のみ）。
- 調号はメロディ譜表の各段頭に描画する（リズム譜表には描画しない）。調号があり、かつメロディを含む楽譜では、全段の小節の開始位置を調号の幅だけ右にずらして小節線を揃える。

### 14.2 リードシートモード (`show_rhythm: false`)
- メロディのある段ではリズム譜表を描画せず、セクション名 → コードネーム → メロディ譜表 → 歌詞 の構成とする。
- 同じ段にメロディのない小節がある場合、その小節にはメロディ譜表上に拍ごとのスラッシュ（ピッキング記号なし）を描画する。
- 段全体にメロディがない場合は、通常のリズム譜表で描画する。

### 14.3 段あたり小節数 (`measures_per_row`)
- 1〜8 の整数で1段あたりの小節数を指定する。範囲外・不正値は警告診断とし、デフォルト 4 を用いる。

title: 風のコンパス - Wind Compass (Acoustic Rhythm Score)
