# GuitarDSL Web application specification

- Status: Current
- Owning Issue: [Issue #180](https://github.com/puchinya/vscode-guitar-dsl/issues/180)
- Related Issues: [Issue #166](https://github.com/puchinya/vscode-guitar-dsl/issues/166), [Issue #172](https://github.com/puchinya/vscode-guitar-dsl/issues/172), [Issue #174](https://github.com/puchinya/vscode-guitar-dsl/issues/174), [Issue #176](https://github.com/puchinya/vscode-guitar-dsl/issues/176), [Issue #178](https://github.com/puchinya/vscode-guitar-dsl/issues/178)
- Related design: [Web application design](../design/web-app.md)
- Related specifications: [GuitarDSL syntax](guitardsl-syntax.md), [VS Code extension](extension.md), [GUI](gui_design.md)

This document defines the public behavior of the browser-based GuitarDSL single-page application (SPA). The VS Code extension remains an independent product with its existing editor, commands, and VSIX package. GuitarDSL syntax and score meaning continue to be owned by the [syntax specification](guitardsl-syntax.md).

## 1. Overview

### Purpose

The Web application provides browser-based GuitarDSL editing, score preview, practice playback, and PDF download. It supports local documents without a Google account and optionally connects to Google Drive after a user-initiated sign-in.

### Scope

This specification covers the Web application's editor, score UI, document identity and persistence, Google Drive connection, local-to-Drive transfer, PDF download, responsive behavior, errors, and privacy boundaries. It does not redefine GuitarDSL syntax or change the behavior of the VS Code extension.

### Normative requirements

The numbered sections below define the Web application's normative behavior. The editor, workspace, storage, Drive, and PDF contracts are separate to keep each user-facing boundary traceable.

## 2. Application and document editing

- The Web application is a static, browser-only SPA. It does not require a dedicated application backend, authentication server, server-side rendering service, or application database.
- The formal browser targets are desktop Chromium and the latest stable Safari on macOS. Support claims are limited to the browser and operating-system versions recorded in implementation status; iOS and iPadOS Safari are outside this target.
- The application MUST open, create, edit, save, list, and delete local GuitarDSL documents in IndexedDB without connecting a Google account. Supported document extensions are `.guitardsl` and `.gdsl`.
- The editable source buffer is the single source of truth for a document. Parsed scores, diagnostics, Preview SVG, Inspector values, playback state, and PDF output are derived from a particular source revision.
- The source editor MUST support line numbers, active-line highlighting, matching brackets, indentation and Tab, line wrapping, search, replace, go-to-line, selection, IME composition, undo, and redo. Syntax highlighting and editing aids MUST preserve the editable source as text and MUST NOT add an independent GuitarDSL parser.
- The editable source buffer is authoritative; editor state is associated with its open tab. The editor MUST retain each tab's selection, scroll position, and undo/redo history when switching tabs or redrawing the workspace. A browser reload MUST restore source and drafts, but is not required to restore undo history.
- A completed CodeMirror transaction MUST be synchronously committed to its owning document key before a workspace redraw, tab switch, or document identity change can replace editor state. A queued edit MUST never be published to whichever tab happens to be active later.
- Before saving a document or starting PDF export, the host MUST synchronously flush completed CodeMirror edits for the target document and use that current source and revision. Save and PDF export MUST stop while IME composition is active and prompt the user to finish composing.
- The native leave-confirmation guard MUST synchronously include unpublished editor edits and active or pending IME composition, as well as draft writes that have not completed persistence. It MUST NOT rely on an asynchronous write started during `beforeunload`.
- The editor MAY normalize line separators for display, but edits MUST preserve untouched original CRLF or CR line endings using the document's source-preservation rules. Input MUST NOT be saved, completed, or replaced before an active IME composition is committed.
- An asynchronous Cut or Paste MUST capture the active tab instance, complete document identity (including account ID for Drive), source revision, source selection, and IME/composition state before awaiting the Clipboard API. After the await, it MUST revalidate all captured values and MUST NOT edit any tab if the active document, revision, selection, or composition state changed. A cancelled stale action leaves source unchanged and reports why. A successful Cut or Paste is one undoable source edit.
- Each user input batch, search/replace, completion, and accepted Preview or Inspector change set MUST be one undoable source edit. A workspace view-mode change or layout resize MUST NOT reset the source, selection, undo history, Preview scroll position, or playback position.
- Completion candidates MUST be deterministic and derived locally from document fields, line prefixes, variables, and syntactically safe DSL constructs. Completion MUST NOT call an AI model or network service.
- Inspector and Preview edits MUST be expressed as source-preserving changes and applied only when their document identity and expected revision still match the current buffer.
- The application MUST support Japanese and English UI, light and dark themes, keyboard operation, and accessible names and states for interactive controls.

## 3. Score workspace and preview

- The Web application uses a Compact IDE workspace. Its reference viewports are 1600 × 900 and 1280 × 800 CSS pixels. The normative panel geometry, controls, and hierarchy are owned by the [GUI screen specification §5](gui_design.md#5-web-compact-workspace).
- The workspace has exactly one global display mode: Source, Split, or Score. Split is the default. The three icon-only controls MUST be mutually exclusive, expose `aria-pressed`, and have Japanese and English `aria-label` and `title` text. The global mode is independent of the Preview's existing normal, edit, and practice modes. Source and Score modes hide the opposite pane and the internal splitter.
- The three workspace view controls occupy the right side of the 36 px document tab row. The workspace MUST NOT add a second title or toolbar row between the tabs and the Source/Score panes. Preview playback and settings controls remain in the Preview's existing 48 px row.
- With no open document tabs, the tab row and editor workspace beneath it MUST show only their theme-appropriate background, with no horizontal separator below the empty tab row. The Source editor, including its gutter, the Score pane, and empty-state text MUST be hidden from the rendered view and accessibility tree. Their stable editor hosts remain mounted. Opening a document shows the panes according to the selected workspace mode and layout.
- Explorer MUST show the localized “On this device” (`このデバイス`) and “Library” (`ライブラリ`) roots at the same time. Each root expands and collapses independently. Both roots use the same 32 px row geometry, with aligned disclosure chevrons, folder icons, and title insets; the Drive row also retains its options menu. The Library root represents the visible GuitarDSL folder at the top level of My Drive; its row has an ordinary folder icon, localized Library label, and secondary Drive connection state. Its folders load lazily as a physical tree. The heading reads EXPLORER in English and エクスプローラー in Japanese; related visible and accessibility labels use the active locale. The functional options menu and library root menu expose their contracted actions. New-score creation asks for a base filename without an extension, defaults to Untitled, and always appends exactly .guitardsl; a typed .guitardsl or .gdsl suffix is stripped case-insensitively before the fixed extension is added. Cancelling the prompt MUST create no local document, tab, active-document change, or creation notice. Local creation and import remain available offline. Library rows remain 32 px in disconnected, connecting, connected, and expired states. A connected root shows account status and accessible child items, not a claim of a complete Drive listing. Drive account and root discovery MUST follow §5; folder selection MUST NOT imply permission to enumerate every child.
- Explorer file rows MUST be 30–32 px high, one line, and include the 16 px SVG file icon. Only the active document row has the selected state. The active row comparison MUST use the complete document identity and, for Drive, the account ID. The selected background MUST NOT use a left-edge accent stripe. Modified time may be exposed as title/accessibility metadata but MUST NOT appear as a second visible row.
- The Inspector heading is 36 px, reads `Inspector` in English and `インスペクタ` in Japanese in both its visible title and accessible pane name, and has an ellipsis menu with exactly Close Inspector and Reset width to default (300 px). The default Web Inspector tab is Variables; its existing empty state is used when the active score has no variables. The Inspector remains above Problems on the right Tool Window Bar, with no duplicate Inspector action in the Activity Bar. The Inspector control MUST show its active state when its saved open state is true.
- A narrow viewport MUST avoid horizontal overflow. When the available width is insufficient, the Inspector and then Explorer are temporarily collapsed in that order. Width-driven collapse MUST NOT overwrite a user's saved manual open/closed state. The user can reopen a collapsed region from its adjacent tool-window control.
- Playback and score settings remain available in the Preview's compact 48 px row. The Preview retains the existing normal, edit, and practice modes. The Inspector provides document, variables, score settings, and chord progression tabs.
- Problems is an independent bottom tool window spanning Explorer, center, and Inspector, while excluding the Activity Bar and Tool Window Bar. It is open by default, can be closed with a far-right × action, and can be resized. Its splitter MUST be hidden together with the panel while closed; reopening restores the panel and splitter without changing its saved height. The Problems Activity Bar control MUST show an active state while the panel is open. Source edits MUST NOT automatically open or close it.
- Problems and editor lint consume the same compiler diagnostics. Its 32 px heading shows the Problems icon, nonzero error/warning SVG icons and counts, and the close action; a zero count MUST NOT produce a badge. The Problems Activity Bar badge MUST be hidden when the total diagnostic count is zero and MUST show the exact total when it is positive. The column headings and rows share aligned Severity, File, Line:Col, and Message columns; desktop rows use `74px minmax(180px,1fr) 72px minmax(250px,3fr)` with a responsive narrow-width equivalent. Each real diagnostic row includes its severity icon, file, 1-based line and column, and formatted message. Selecting a diagnostic switches to Source mode and reveals and focuses its compiler-provided source range. An empty list displays “No problems” and no notification badge. The old diagnostic list below the source editor is not shown.
- The Web header uses the repository GuitarDSL sidebar SVG, the product name, and exactly three menus: File, Edit, and View. It MUST NOT show a Window menu or a storage label beside the product name. Menu triggers and dropdown rows use conventional compact spacing. Only the currently hovered or keyboard-focused row receives the selected background; checked rows retain their accessible checked state and check indicator without a persistent selected background. File, Edit, and View actions follow the menu contract in [GUI screen specification §5.4](gui_design.md#54-header-menus-and-actions). On the right, Google Drive state, Save, PDF, Help, and the rightmost Settings control are shown without permanent button frames; there is no separate Account control. The Google Drive menu provides Connect or Reconnect when signed out, a disabled Connecting row while authentication is pending, and—when connected—the signed-in account identifier (`emailAddress`, falling back to account ID), a separator, and Disconnect. It does not show a stale identity when disconnected or reauthentication is required. Help opens the same-origin Web Help in a separate browser window and provides a usable fallback when popups are blocked.
- Transient workspace notifications, including successful local score creation, MUST appear as non-blocking snackbars outside document flow, with no action buttons. Informational notices MUST dismiss automatically after 4 seconds and errors after 8 seconds. A newer notice replaces the current notice and restarts its timer. Notice text remains available through a polite status or assertive alert role according to severity. All notices MUST render through a reusable `Snackbar` component, which owns presentation, accessibility semantics, and its per-kind dismissal timer; the workspace runtime owns message content and severity and receives a typed dismissal command when the timer expires.
- All four workspace splitters support pointer dragging and cancellation, resetting only their own size on double-click, and keyboard resizing through a focused `separator`. The Source/Score splitter MUST update both rendered pane widths while dragging and persist the resulting center ratio. Each splitter exposes orientation, min/max/current values and a visible focus ring. Clamping MUST prevent negative sizes, non-finite geometry, and horizontal overflow.
- Workspace display mode, panel open state, widths, heights, and center split ratio MUST be persisted and restored. Invalid saved preferences fall back to defaults. Temporary width-driven collapsing MUST NOT replace the user's saved manual open/closed state.
- The application MUST provide Japanese and English UI, light and dark themes, keyboard operation, and accessible names and states for interactive controls.
- Explorer and Inspector ellipses MUST open keyboard-accessible menus with the specified actions; Escape returns focus to the invoking control. The `ic-down`/`ic-right` disclosure icons are reserved for tree roots, `ic-more` for panel options, and `ic-close` for closing Problems. The approved SVG paths are used through the Web icon sprite.
- The Web shell MUST use File/Edit/View menus with contracted commands, platform shortcuts, accessible keyboard navigation, disabled states, and focus return. In Dark theme, hovered or keyboard-focused menu items and shortcut text MUST remain readable against the selected surface. The editor's native context menu and browser-reserved shortcuts remain available. Opening a menu MUST NOT alter source, revision, document identity, drafts, playback, or splitter state.
- Web-host dark chrome uses #202229 header, #22252C tool windows, #333F59 selected file, #424652 boundaries, #7692F4 selected accent, and #99A3B5 muted text. This host palette MUST NOT style the score iframe. The shared Preview toolbar and shared VS Code score/Inspector rendering remain unchanged by this Web-only panel work.
- Score rendering, playback order, timing, source-preserving edits, and other shared GuitarDSL behavior MUST use the same core implementation as the VS Code extension. The Web application MUST NOT introduce a second parser, score model, play-order resolver, timeline, or rendering interpretation.
- A view-mode change or splitter drag MUST resize the existing Preview without unnecessarily recreating its iframe. The Preview and Inspector audio lease and Preview playback position MUST remain intact.
- Score rendering, playback order, timing, source-preserving edits, and other shared GuitarDSL behavior MUST use the same core implementation as the VS Code extension. The Web application MUST NOT introduce a second parser, score model, play-order resolver, timeline, or rendering interpretation.
- Preview and Inspector audio use one exclusive playback lease. Preview playback or practice and Inspector audition MUST NOT play at the same time.
- Closing a tab, switching storage sources, or refreshing the browser MUST preserve recoverable drafts. A storage switch MUST NOT silently change the identity or contents of documents already open in tabs.

## 4. Document identity and persistence

- A document is identified by `{storage, fileId}`. A local document and a Drive document with the same name are different documents.
- Opening a document more than once MUST focus its existing tab rather than create a duplicate. Different document IDs remain separate even when their names match.
- The active document identity MUST be checked again after every IndexedDB await and immediately before adding a tab. Concurrent opens of the same identity MUST result in one tab. Concurrent close operations MUST recalculate the target tab's current position immediately before removal; a close requested twice MUST remove the tab once, and a close operation MUST NOT remove a different tab after another close completes. Repeated requests for the same in-flight close MUST return the same awaitable operation so every caller waits for draft persistence and tab removal to finish.
- Local source and recoverable drafts MUST persist in IndexedDB. Tab session state needed to restore open documents after refresh MUST also be recoverable without storing credentials.
- The application MUST track each tab's last successfully persisted draft revision and source. If any current tab has changes that have not completed persistence, including an unpublished editor edit, active or pending IME composition, or a pending or failed IndexedDB write, navigating away MUST trigger the browser's native leave confirmation. The application MUST NOT rely on asynchronous writes started from `beforeunload` to preserve source. A user who stays on the page can wait for the saved state or export the source if persistence fails.
- A Drive appData change MUST first be stored as a strictly validated, account-keyed pending metadata record in IndexedDB before its visible local state is committed. The record contains only the validated Drive appData state, account ID, schema version, and update time; it MUST NOT contain score source, document IDs for local files, drafts, OAuth tokens, or email addresses. The record remains pending after offline state, a failed or uncertain PATCH, reload, disconnect, or `pagehide` until a matching remote readback is verified or the user explicitly chooses remote state.
- On reconnect, the app MUST compare that account's pending metadata with remote appData and ask the user which state to apply when they differ. Choosing remote state MUST update the selected folder, Explorer, and open/active Drive references while retaining recoverable local drafts; it MUST NOT resubmit the rejected local state. Pending data for one account MUST never be read or applied under another account. `beforeunload` warns for pending or failed appData changes; `pagehide` MUST NOT start a network write.
- A visible saved state may be shown only after the corresponding storage operation succeeds. If IndexedDB is unavailable, the application MUST state that it cannot persist the document and provide a download path; it MUST NOT claim that unsaved text was saved.
- Local import and export MUST remain available when Google authentication, Drive, or network access is unavailable.

## 5. Google Drive

- Drive is optional. Users MUST be able to create, edit, save, and export local documents without signing in. The local root remains independent from the GuitarDSL Library.
- Authentication uses the Google Identity Services browser token model. The access token is held in memory only. The requested scopes are exactly https://www.googleapis.com/auth/drive.file and https://www.googleapis.com/auth/drive.appdata; no full-Drive or metadata-wide scope is allowed. The app MUST verify both scopes before accepting the account or making Drive requests. Partial consent leaves the user disconnected or explicitly requiring reapproval.
- A deployment supplies only a public Web OAuth client ID, a referrer-restricted Google API key, and its Google Cloud project number through Vite settings. No OAuth client secret is used in browser code.

### GuitarDSL Library root

- The Explorer display label for the Drive root is `Library` in English and `ライブラリ` in Japanese; the physical Drive folder remains named `GuitarDSL` at the top level of My Drive. The library consists only of that app-managed root and real folders and score files created or imported into it. It is not a Drive-wide mirror, virtual folder, or complete synchronization claim.
- On connection, discover the accessible top-level My Drive folder named GuitarDSL. Reuse that same folder ID; the current appData selectedFolderId may identify it only after its name, folder MIME type, and My Drive root parent are verified. When the canonical folder has no app marker, set appProperties guitardslLibraryRoot=1 and read it back before committing selectedFolderId or the tree. Ask for confirmation only when creating a new root because no eligible existing root is available.
- Do not migrate an arbitrary previous folder ID or old local Drive-folder setting. Do not copy, move, or delete content from another folder. A folder elsewhere or with another name is outside this library. The appData schema version 1 remains the current format, and selectedFolderId records the verified canonical root.
- The app MUST NOT ask Picker to select a destination folder. The only Picker flow is for importing files into the library.

### Library tree and file operations

- The tree contains real Drive folders and supported GuitarDSL files. Each folder is listed one level at a time from its parent, with files.list pagination and trashed=false. The app lazily loads a folder when expanded and invalidates that folder's cache on explicit refresh. It MUST NOT recursively mirror the entire Drive tree.
- Score rows are limited to .guitardsl and .gdsl files. A folder selection or parent relationship does not authorize every child under the drive.file scope. Show only accessible, app-created or individually authorized children, and never describe a listing as complete. Direct edits made in Drive to items not authorized for this app are not promised to appear.
- The root and child folders allow create, rename, expand/collapse, and open-in-Drive. Folder move and folder trash are not offered because they can affect children outside the app's authorization. A newly created folder is a child of the clicked library folder.
- Before creating a folder or score, or copying a Picker file, revalidate the current library root and target folder from live Drive metadata, including their physical parent chain. A cached Explorer row is not proof that a folder is still inside the library. Recheck after the user returns from Picker and immediately before each copy. If the root or target has moved, been trashed, or lost access, perform no write. After a write, read back the new item and verify its ID, parent, type, name, and content as applicable before reporting success.
- The library allows new scores, score rename, duplicate, move between folders inside the same library, download, PDF export, and move-to-trash. Score rename uses a metadata update and retains the same fileId, parent, source, and extension. Duplicate creates a new fileId. A move changes only the parent within the confirmed library. Trash requires confirmation and is not permanent deletion; an open tab or unsaved local draft is retained until the user explicitly resolves it.
- Normal Drive save updates the existing fileId with media PATCH. It never creates a per-save copy. Before an update, compare version, modifiedTime, and headRevisionId with the last-read values; a detected mismatch aborts the write and preserves the draft. Saves to the same accountId and fileId are serialized. Read the source back and report success only after identity and content match. Edits made while saving remain a draft. GET-to-PATCH is not atomic; a concurrent write from another device may still be overwritten and this limitation is disclosed.

### Import from Google Drive

- Google Picker is for file import only. Folder selection, destination selection, direct editing of the Picker source, and folder-wide import are prohibited. Multiple files may be selected.
- Each selected file is validated as a supported GuitarDSL extension and has Drive MIME type `text/plain` or `application/octet-stream` in both the Picker selection and the source metadata read immediately before COPY. Unsupported types are rejected before writing. Read the copy back by its new fileId and verify its parent, name, allowed MIME type, and contents against the source before showing it as imported. The original fileId and contents remain unchanged. Google Docs/Sheets, folders, unsupported MIME types, and unsupported extensions are rejected.
- A same-name destination requires an explicit rename or skip choice; an existing file is never overwritten. A multi-file import reports each result, including partial failures, and offers retry only for a confirmed failed item.
- Cancel, invalid selection, or an unavailable target folder performs no Drive write and does not change tabs, source, selected library, or saved state. Before each import or duplicate `files.copy`, persist an account-scoped IndexedDB recovery record with its operation ID, source ID, target folder, requested name, operation kind, and the UTF-8 SHA-256 digest of the source content; never store the source text in that record. Mark that the request may have been sent before issuing it and record the returned copy ID when available. Keep the record until the copy's ID/marker, parent, name, allowed MIME type, and content digest are confirmed. On reconnect, reload, or repeat action, reconcile the existing record first; an unresolved result MUST NOT trigger a new copy or be reported as definitely failed. A legacy operation record without a digest may be confirmed only by re-reading the source and matching that current content against the copy; if either side cannot be read or the content differs, retain it as unresolved without another COPY.

### Open in Google Drive

- The root, each library folder, and each library score expose a context-menu item named Google Driveで開く / Open in Google Drive through both right-click and Shift+F10. Local documents do not expose it.
- A folder opens https://drive.google.com/drive/folders/{encodeURIComponent(folderId)}. A file opens its verified HTTPS Drive-domain webViewLink when available, otherwise https://drive.google.com/open?id={encodeURIComponent(fileId)}. The URL is built from the clicked row's ID, never the active tab's ID.
- Menu creation captures accountId, Drive generation, fileId, and item kind. The action revalidates this context before opening a new tab with noopener,noreferrer. An old menu after account switch is inert. If a popup is blocked, provide a direct clickable link; a null window.open result alone does not indicate failure. Opening a link does not modify source, undo history, tabs, selection, expansion, save state, or synchronization state. Explain that Drive access depends on the Google account selected in the new tab.
- After any Picker, read, create, copy, rename, move, trash, conflict decision, or storage write, verify that the captured account, Drive API instance, generation, and target IDs still own the operation before applying a result. A result from an ended account session is discarded.

### Drive application state

- The app stores one account-scoped guitardsl-state-v1.json (application/json) in Google's hidden appDataFolder. It contains exactly schemaVersion: 1, selectedFolderId: string|null, folderPrompt: unasked|deferred|completed, openDriveFileIds: string[], activeDriveFileId: string|null, and recentDriveFileIds: string[]. Open IDs are ordered, unique, and capped at 30; recent IDs are unique, most-recent-first, and capped at 50. IDs are opaque references and do not grant file access.
- AppData MUST NOT contain score source, local document IDs, drafts, undo history, OAuth credentials, email addresses, or per-device layout preferences. Local documents, drafts, and layout remain in IndexedDB. The current appData schema is read directly; older drive-folder:<accountId> and workspace-drive:<accountId> IndexedDB settings are not imported.
- To find app state, paginate files.list with spaces=appDataFolder, trashed=false, an exact name filter, and a MIME check. Read an existing candidate by ID. Create the JSON file only when no valid candidate exists. Initial creation uses one files.create with parents:['appDataFolder']; ordinary saves update that same ID and succeed only after readback matches.
- If duplicates already exist, select the canonical file by oldest createdTime, then lexical ID, warn, and retain all copies. A possibly lost initial POST response gets one re-list/read, never a blind second POST. Before PATCH, compare version and modifiedTime with the loaded baseline. A mismatch offers Load Drive settings or Use this device; do not PATCH without the user's choice. Loading remote settings validates the library root, updates Explorer and Drive tab references, preserves local drafts, and does not resubmit the local choice.
- Invalid JSON, unknown schema versions, permission failures, offline state, unresolved POST/PATCH results, and conflicts remain visible and MUST NOT silently create a replacement or discard pending changes. Changes serialize per account, debounce for about one second, and remain pending across offline state, disconnect, and reload. A validated account-keyed IndexedDB pending record is written before a setting is committed locally and clears only after matching remote readback or an explicit remote-state choice. If appData cannot synchronize, explicit disconnect remains available after confirmation; pending metadata and local drafts remain available for the next connection. pagehide MUST NOT issue POST/PATCH. Every async result is applied only while its captured account, Drive instance, and generation still own it.
- After authentication, remote appData state loads before Drive tabs or library rendering. A remembered file ID remains only a reference: revalidate it through drive.file and ask the user to authorize it through Picker again on 403/404.

## 6. PDF export

- PDF export downloads a PDF generated from the same score-page SVGs used by the Preview and VS Code extension. Output preserves the common page layout, Japanese text, TAB, chord diagrams, and multiple pages.
- Browser export MUST not require a server. It uses a browser download, and font bytes needed for Japanese output are provided to the PDF renderer without introducing Node-only file APIs into browser code.

## 7. User-visible behavior

### Observable behavior

- After startup without Google authentication, users can create and edit a local document, see diagnostics and score Preview, use the Inspector and playback, retain a draft through refresh, and download a PDF.
- Explorer keeps This device (`このデバイス`) and Library (`ライブラリ`) visible together with aligned root-row geometry. Local create/import/export/delete actions remain available offline. Library actions require connection; open tabs retain their original {storage, fileId} identity when the account or library changes.
- The library root shows its connection and access state, accessible folder tree, loading, empty, and error states. It never claims to show every Drive child. Folders load lazily. Local documents and drafts remain available if a library request fails.
- Selecting the same file twice selects the existing tab. Closing a tab retains its local draft and any recoverable Drive draft. Closing the last tab leaves the tab row and editor workspace beneath it as theme-colored background only, with no horizontal separator below the tab row; the Source editor, gutter, Score pane, and empty-state text are hidden from view and accessibility while stable editor hosts remain mounted. Opening a document restores the selected workspace mode and layout.
- The Preview and Inspector show derived state for the active document revision. An edit from either surface either applies to that same revision as one source edit or makes no source change and reports that the edit is stale.
- A Drive save reports success only after the remote operation succeeds and readback matches. Authentication cancellation, unavailable or unauthorized files, version conflicts, and network errors leave local source and drafts available for retry or export. A PATCH 401 offers explicit reconnect; a PATCH 403 remains a permission error and does not start an authentication loop.
- If another device saves at nearly the same time, its changes may be overwritten during the accepted GET-to-PATCH race. The library and Help disclose this limitation. Detected preflight conflicts stop without writing.
- A new Drive library root is never created without explicit confirmation. An accessible top-level My Drive/GuitarDSL folder is reused under its existing ID and marked if needed. Arbitrary old folder IDs and legacy local Drive-folder settings are not migrated; their folders and files are left untouched.
- Import from Google Drive copies each selected supported score into the library under a new fileId. The original remains unchanged. Cancellation and rejected files cause no copy. Same-name files require a rename or skip choice; partial results are reported per file, and unknown results are never blindly retried.
- Folder creation and rename affect the clicked library folder. Folder move and trash are unavailable. Score rename retains its fileId, contents, extension, and parent. Copy creates a new ID. Move is limited to library folders. Trash requires confirmation and preserves open tabs and drafts until resolved.
- Google Driveで開く / Open in Google Drive appears on the library root, every child folder, and every library score, through right-click and Shift+F10. It opens the clicked item's Drive URL in a new tab, does not change workspace state, and becomes inert if its captured account/generation is stale. A blocked popup exposes a direct link.
- Local-to-Drive move reports completion only after remote readback verification and local deletion. On partial failure it reports which copy remains and preserves a retryable identity.
- If local persistence is unavailable, the UI clearly communicates that the current text is not saved and offers download.
- Problems and editor lint display the same compiler diagnostics in the same order and with the same source ranges. Selecting a problem switches to Source mode and focuses its source range; zero results show an explicit empty state.
- Help opens a local Japanese/English dialog with a table of contents for basic operation, editing, Preview, Drive, and shortcuts. Closing with Escape or the close button returns focus to the Help control. Settings opens a local menu for system/light/dark theme, Japanese/English language, and confirmed layout reset.
- Right-click, Shift+F10, and the Context Menu key open host-owned menus for Explorer roots and files, document tabs, Problems rows, Preview notation, and the source line-number gutter. Right-click within the source editor text body keeps the browser's native editing menu for cut, copy, paste, IME, and selection.
- The local root menu offers New score and Import file. The library root menu offers, in order, New score, New folder, Import from Google Drive, Refresh, Open in Google Drive, and About this library. A library folder menu offers Open/Close, New score, New folder, Import here, Rename, and Open in Google Drive. It does not offer folder move or delete. A library score menu offers Open, Rename, Duplicate, Move to folder, Download a copy, Export PDF, Open in Google Drive, and Move to trash.
- The local file menu keeps Open, Rename, Duplicate, Download, Download as PDF, Move to Google Drive, and Delete in that order. Move to Google Drive appears only while Drive is connected and a destination folder is selected. Rename prompts for the basename only and keeps the original .guitardsl or .gdsl extension fixed; extensionless names remain extensionless. Canceling or entering only whitespace changes nothing, while a successful rename retains file identity and source. Duplicate names use the smallest unused positive (n) suffix before .guitardsl or .gdsl, or at the end of a name without either extension. Name uniqueness is case-insensitive after Unicode NFC normalization. Download and PDF actions use the clicked file's current source regardless of which tab is active. Local Delete asks for confirmation and closes the selected file's open tab.
- Every menu action captures the clicked item identity and revalidates it before acting. Drive actions also revalidate account and generation; stale targets are discarded. A document tab menu offers Open this tab, Close other tabs, Export source, and Close, with Move to Drive when applicable.
- A Preview notation menu offers Go to source position only when the clicked visual element has a current visualSourceBinding; otherwise that item is disabled. It also offers PDF export. The Preview message carries the binding ID and {documentUri, documentVersion, previewGeneration}; the host validates all four values again when the action runs.
- Explorer, tab, Problems, and Preview menus expose only applicable actions and close within the viewport. Menus support arrow keys, Home/End, Enter/Space, Escape, outside click, disabled state, and focus return to the invoking element.
- Copy-message actions report Clipboard API failures rather than claiming success. Destructive local deletion asks for confirmation. The drive.file score-file boundary and the appData-only drive.appdata boundary remain separate.

## 8. Errors

### Error and boundary behavior

- **IndexedDB unavailable or quota/write failure:** retain the in-memory buffer, do not display a saved state, explain the persistence failure, and provide a download route.
- **Invalid GuitarDSL:** retain the source, show the compiler diagnostics, and render only the valid derived state permitted by the shared compiler contract.
- **Stale Preview or Inspector edit:** reject the entire change set without editing the source and refresh derived UI from the current revision.
- **Authentication cancelled, expired, or unavailable:** retain local tabs and drafts, do not report a Drive save, and allow a user-initiated retry.
- **Drive 401/403/429/5xx, offline, or readback mismatch:** retain source and drafts, report that the save was not confirmed, and never automatically resend the PATCH. For an unknown result, read Drive once to determine the observed remote state; a later retry requires an explicit user action. A PATCH 401 also marks the current Drive authorization as expired and offers an explicit reconnect action; after reconnect, the user reviews the remote state before retrying. A PATCH 403 is reported as an access-permission failure and does not trigger an automatic authentication prompt or reconnect loop.
- **Drive version mismatch:** perform no overwrite; offer reload from Drive, save the local draft under another name, or cancel.
- **Different-device write between preflight and PATCH:** the app cannot detect this race atomically; the concurrent write may be overwritten as described in §5. Do not describe this behavior as conflict-free or lossless.
- **Account or folder changes:** keep local identity separate from Drive identity and prevent cached documents from another account being shown as the active account's files.
- **Move interrupted or partially completed:** keep the local original until the remote copy has been read back and verified. Repeated retry MUST be idempotent with respect to the already-uploaded remote file.
- **PDF conversion or download failure:** preserve the source and report that no successful export occurred.
- **Audio or worker failure:** stop or release the affected playback lease and leave document source unchanged.
- **Invalid saved layout value:** fall back to the affected panel's default without negative or non-finite geometry. A width-driven collapse is transient and does not replace the stored manual state.
- **Stale context-menu target or source binding:** perform no action and close or discard the menu. Clipboard denial is reported as a copy failure.
- **Splitter cancellation or hidden pane:** release pointer capture and event listeners; subsequent resizing MUST not change a different pane's stored dimensions.

## 9. Privacy

### Security and privacy

- Google access tokens are short-lived in-memory values and MUST never appear in persistent browser storage, URLs, console output, or document data.
- Normal saves update the existing Drive file and do not create hidden per-save copies. Drive revision history is only an auxiliary recovery option; older revisions are not guaranteed to remain available indefinitely.
- The app requests exactly `drive.file` and `drive.appdata`. The latter is used only for the single appData state JSON; score files remain within the `drive.file` authorization boundary. Visible Drive list results are treated as access-limited, not proof that a selected folder has been exhaustively enumerated.
- AppData contains only the documented selected folder and Drive file-ID references. References do not grant access; each remembered score file is reopened through Drive authorization. Local document IDs and source remain in IndexedDB. Tokens, email, score content, and drafts are never copied to appData.
- User-authored DSL, file names, Drive metadata, and rendered score content are untrusted input. HTML and SVG insertion paths MUST escape or safely construct text and attributes; untrusted content MUST NOT become executable markup or script.
- OAuth account identity is kept separate from local document identity. Switching accounts MUST NOT mix one account's cached remote metadata into another account's view.
- The browser app does not send document text to an application server. Drive API requests are made only for user-authorized Drive operations.
- The production service worker MUST cache only same-origin, built static assets. It MUST NOT cache Google Identity Services, Google Picker, OAuth or Drive/API responses, authorization headers, GuitarDSL source, PDF Blobs, or IndexedDB data.

## 11. Offline access, installation, and updates

- The Web app MUST provide a root-scoped installable PWA with the GuitarDSL name, a standalone display mode, and 192 px, 512 px, maskable 512 px, and Apple touch icons. The app MUST remain a static application; installation does not add a backend or change document storage ownership.
- The first load and service-worker installation require an online visit. After successful installation, the service worker MUST precache the same-origin production HTML, JavaScript and CSS chunks, SVG assets, PDF fonts, and PWA icons so the app can start and render PDFs offline. Service-worker registration MUST be disabled on the development server. A service-worker failure MUST leave ordinary online app use available.
- When offline, users MUST be able to start the installed app, open and edit Local IndexedDB documents, restore Local drafts, view Preview, and export a PDF. The app MUST disable Google Drive listing, Picker, authentication, and remote save actions and clearly show that Drive is unavailable. Local drafts MUST remain labeled as local and MUST NOT appear remotely saved.
- An available app update MUST appear in an explicit prompt with **Update** and **Later** choices. A waiting service worker MUST NOT activate itself, take control of existing clients, or reload the page. Choosing **Later** keeps the current app running.
- When the user chooses **Update**, the app MUST acquire an exclusive preparation gate synchronously before its first asynchronous wait. While the gate is held, workspace input and commands MUST be blocked and no new Drive or appData operation may start. The app MUST synchronously flush completed CodeMirror edits, reject active IME composition, persist every open-tab draft to IndexedDB, and confirm that Drive media operations and appData queues/timers are idle. After each asynchronous wait and immediately before activating the worker, it MUST revalidate the open documents' identities, source revisions, editor/IME state, draft writes, and Drive/appData quiescence. A failed check MUST keep the waiting worker inactive, explain the reason, and release the gate so editing and saving can resume. The app MUST stop Preview and Inspector audio before explicitly activating the waiting service worker and reloading; a failed activation also releases the gate. The prompt MUST disclose that reload can discard CodeMirror undo history.
- The update gate MUST cover every command and asynchronous workspace action from its entry point, including editor clipboard continuations, local create/import/open/close/activation, explicit Save (including its initial local-draft write), Explorer refresh, settings callbacks from shared Inspector hosts, and Drive/appData work. The controller MUST register an action before invoking it, synchronously reject newly arriving actions after the gate starts, and account for already-started actions until they settle. Update preparation MUST wait for those actions or fail safely before reload; an explicit Save already accepted MUST be allowed to report its remote result, and a failed/incomplete remote Save MUST leave the local draft recoverable and report that remote saving did not complete. Every asynchronous continuation that can edit source, change workspace state, or start another request MUST revalidate its operation generation and lifecycle/gate state before applying that effect. Clipboard promises that resolve after update preparation starts MUST not dispatch a source edit and MUST report that the edit was deferred. A persisted `pagehide` MUST invalidate pending continuations before suspending the page; they MUST NOT apply a source or workspace mutation while suspended or after a later `pageshow` resumes the same runtime.
- A Drive file-open command MUST validate its captured `accountId` against the current connected account, Drive session generation, and current row ownership before starting or applying the open. A command captured under account A MUST not open a same-ID row under account B.
- Drive Explorer list refreshes MUST use latest-request-wins ordering within the same account, Drive instance, generation, and folder. Both successful rows and failures (including 401) from an older request MUST be ignored. Before issuing a Drive list after local IndexedDB work, and before applying its result, the controller MUST recheck the operation generation, online state, and current account/folder/session.
- Production PWA offline acceptance MUST cover both warm offline reload and cold start from a previously installed persistent browser profile. The cold-start case MUST close the first browser context, relaunch a persistent context with the same profile while offline, and then start from service-worker/cache/IndexedDB state. It MUST restore a Local document, edit it, render Preview, and export a valid PDF. An isolated new context without the same browser profile does not satisfy this case.
- Compiler results and line-to-offset indexes used by workspace snapshots MUST be cached by document identity, revision/source, locale, and parse options. Cursor/selection-only snapshots MUST reuse the current parsed result and diagnostic offsets. Tests MUST show that 100 selection changes add no parse calls, one source revision causes one new parse, and diagnostic location conversion reuses precomputed line offsets.
- The update prompt MUST be a non-modal, accessible notification while workspace editing remains available. It MUST have an accessible name and announce update availability and changed preparation status without claiming `aria-modal="true"` or trapping keyboard focus. Keyboard users MUST be able to keep editing while the notification is visible and reach its Update/Later actions in normal tab order.
- When `pagehide` has `persisted === true`, the browser is preserving the document for back/forward cache (BFCache). The app MUST keep the same workspace controller, CodeMirror EditorView, DOM owners, and runtime listeners; it MUST stop Preview and Inspector audio and suspend interaction without disposing the workspace. On `pageshow` with `persisted === true`, it MUST reconcile each open tab's saved/draft baseline from IndexedDB before resuming interaction. If a write committed while its continuation was invalidated, a baseline matching the open source and revision MUST be adopted; if the previous baseline remains current, the open draft MUST be retried after resume. If another version is present or IndexedDB cannot be checked, the app MUST preserve both the editor and stored contents, avoid overwriting either, and explain the recovery action. Stale write successes and failures MUST NOT update the resumed tab's status or messages. Audio MUST NOT resume automatically. Every persisted `pagehide` MUST advance the lifecycle generation and capture a fresh suspension baseline, including while a prior `pageshow` is still reconciling drafts. A repeated persisted `pagehide` MUST invalidate that in-progress reconciliation without repeating runtime disposal or audio shutdown. Only the latest `pageshow` reconciliation may unlock interaction, release the Preview audio lock, or start deferred Explorer, Drive, or appData work. A non-persisted `pagehide` or component unmount MUST dispose runtime resources once and invalidate every pending reconciliation. Neither kind of `pagehide` may start asynchronous persistence or network writes.
- The service worker MUST use no runtime network caching. Its precache MUST contain only files emitted by the same-origin production build. Google Identity Services, Google Picker, OAuth and Drive/API requests, authorization data, GuitarDSL source, PDF Blobs, and IndexedDB content MUST stay outside Cache Storage. Separate development and production origins MUST have separate service-worker scopes and caches.
